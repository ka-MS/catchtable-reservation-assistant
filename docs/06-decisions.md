## ADR-0001 - 제공 형태: Chrome 확장 프로그램

**일자:** 2026-07-10  
**상태:** 채택

**결정:** 별도 데스크톱 앱이 Chrome을 제어하는 방식 대신 Manifest V3 Chrome 확장 프로그램으로 만든다.

**이유:** 사용자의 기존 로그인 세션이 열려 있는 탭에서 직접 DOM을 감시하고 클릭하므로 별도 프로세스, 브라우저 프로필, 자동화 연결 계층을 추가하지 않는다. 초기 실행과 동작 경로가 더 가볍다.

**대안:** Playwright 등의 데스크톱 브라우저 제어. 실사용 Chrome 프로필 연결과 운영 복잡도가 커 1단계에 적합하지 않다.

## ADR-0002 - UI와 언어: TypeScript + 순수 HTML/CSS

**일자:** 2026-07-10  
**상태:** 채택

**결정:** React와 UI 프레임워크를 사용하지 않는다. TypeScript를 컴파일해 Side Panel과 Content Script에서 사용한다.

**이유:** 자동화 성공 속도는 Content Script의 DOM 감시와 클릭 경로가 좌우한다. 1단계 UI는 조건 입력과 상태 표시만 필요하므로 프레임워크의 초기화 비용과 의존성이 이점보다 크다.

## ADR-0003 - 감지 방식: `document_start` + `MutationObserver`

**일자:** 2026-07-10  
**상태:** 채택

**결정:** Content Script를 `document_start`에 주입하고, 예약 UI의 변화는 `MutationObserver`로 감지한다.

**이유:** 반복 새로고침이나 짧은 주기의 폴링보다 페이지에 반영된 변화를 빠르게 처리하고 불필요한 요청을 줄인다.

---

## ADR-0004 - 지속 재시도: 상태 기반, 사용자 중지 또는 마감까지

**일자:** 2026-07-10  
**상태:** 채택

**결정:** 재시도는 성공, 사용자 중지, 종료 시각, 사용자 확인 필요 상태 중 하나에 도달할 때까지 유지한다. 같은 요소의 연속 클릭이나 무제한 새로고침은 하지 않는다.

**이유:** 클릭 성공 후의 화면 전환을 확인하지 않으면 중복 동작과 잘못된 예약 흐름이 생길 수 있다. 대기열, CAPTCHA, 로그인 만료, 결제 확인은 자동화가 처리할 영역이 아니다.
