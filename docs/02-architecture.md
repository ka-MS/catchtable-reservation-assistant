# 02. 아키텍처

## 구성

```text
Side Panel
  -> 조건 입력 / 시작·중지 / 상태 표시
  -> Service Worker
  -> Content Script (캐치테이블 예약 탭)
  -> DOM 감시 / 조건 판정 / 클릭 / 결과 검증
```

## 책임 분리

| 구성 요소 | 책임 |
| --- | --- |
| Side Panel | 사용자가 조건을 입력하고 감시 상태와 결과를 확인한다. |
| Content Script | 페이지 DOM을 관찰하고, 조건이 맞으면 지연 없이 클릭한 뒤 전환 결과를 검증한다. |
| Service Worker | 탭 연결, 컴포넌트 간 메시지, 설정 저장, 브라우저 알림을 담당한다. |
| `chrome.storage` | 예약 조건과 마지막 상태, 결과 이력만 보존한다. |

## 성능 원칙

- Content Script는 `document_start`에 주입한다.
- `MutationObserver`로 렌더링된 예약 UI 변화를 감지한다.
- 조건 판정과 클릭은 Content Script 안에서 완료한다. 클릭 시점에 Service Worker 왕복을 기다리지 않는다.
- 외부 라이브러리와 원격 코드를 사용하지 않는다.
- 설정은 실행 중 메모리에 유지하고, 저장소 쓰기는 설정 변경과 결과 기록으로 제한한다.

## 상태와 재시도

상태 전이와 재시도 종료 조건은 [상세 스펙](specs/01-reservation-automation-spec.md#5-자동화-상태-전이)을 따른다. 지속 재시도는 사용자가 중지하거나 종료 시각에 도달할 때까지 상태를 유지하는 것이며, 무제한 새로고침이나 연속 클릭이 아니다.

## 페이지 어댑터

캐치테이블 DOM 선택자와 화면 판별은 실제 예약 플로우를 확인한 뒤에만 작성한다. 첫 구현에는 단일 예약 플로우만 지원하며, 여러 사이트/플로우를 위한 추상 어댑터는 만들지 않는다.
