# 2026-07-12-09 시계 경계 합의 검증

## 배경

worklog 08의 샘플별 계측이 오프셋 점프의 원인을 확정했다: **응답 서버 풀 간 시계 편차**(site-behavior §8 갱신). 실런 초기 보정에서 로컬 경과 ~200ms 동안 Date 헤더가 2초 점프하는 교차 풀 샘플이 관측됐고, boundary 방식이 이 가짜 초 경계를 잡아 오프셋을 +1137ms로 오염시켰다(같은 보정의 나머지 4개 샘플은 −50ms 근방에서 선형 정합). 실런 3회의 보정 4건이 모두 ~−50 / ~+1100 두 군 중 하나에 안착 — 어느 풀의 경계를 잡느냐가 복불복이었다.

## 변경 (`shared/clock.ts` `selectClockEstimate`)

1. **틱 델타 검사** — 인접 샘플 간격이 1초 미만이므로 진짜 초 경계는 Date 델타가 정확히 +1000이어야 한다. d2000 같은 점프 쌍은 경계 후보에서 제외.
2. **과반 합의 검증** — 각 후보 경계의 오프셋으로 전체 샘플의 Date 헤더를 역예측(`floor((midpoint+offset)/1000)*1000 === serverDateMs`)해서, 과반 이상을 설명하는 경계만 채택. 동표는 midpoint 간격이 좁은(정밀한) 경계가 이긴다. 과반 미달이면 기존 median 폴백.
3. `sampleCount`(metric의 `clockSamples`)는 boundary 경로에서 고정 2 대신 **합의 지지 샘플 수**를 보고한다.

이번 실런의 오염 케이스에 적용하면: 가짜 경계(지지 1/5)가 기각되고 median −43ms가 선택된다(진짜 값 −50 근방).

## 한계 (기록)

floor 재예측은 샘플당 ±1초의 여유가 있어 **1초 미만으로 위장한 교차 풀 경계**(풀 편차 ≈ 1000+δ, δ가 작을 때)는 동표까지 갈 수 있다. 이때는 정밀도 타이브레이크로 결정되며 완전한 판별은 아니다. 샘플 수를 늘리면(현재 설정 3~9) 외래 샘플의 모순이 누적돼 판별력이 올라간다. 다음 실런들의 `clockSampleDetail`로 위장 케이스 실재 여부를 계속 관찰한다.

## 검증

`npm run check` 194개 테스트 green (신규 3: 교차 풀 기각→median, 진성 경계 5/5 유지, 위장 동표의 정밀도 타이브레이크). dist·independence 게이트 통과. 초기/최종 보정이 같은 군에 안착하는지는 다음 실런에서 확인한다 — 두 값이 ±150ms 안에서 일치하면 성공.
