# 2026-07-12 승인제 안내 시트 자동 진행·홍보 인터스티셜 자동 닫기

## 배경

이시즈에 실전 런(11:54)이 슬롯 클릭 후 5초 시간초과로 인계됐다. 라이브 재현 결과 승인제 매장의 `레스토랑 확인이 필요한 예약입니다.` 안내가 `role="dialog"` 없는 `role="presentation"` 바텀시트(MUI Drawer)로 떠서 dialog 판정에 전혀 잡히지 않았다. 같은 매장에서 `예약하기` 클릭을 삼키는 홍보 인터스티셜(`비슷한 곳 둘러보기`, role 없음)도 실측했다. 상세 실측은 site-behavior §7.2.

## 수정

- 후속 판정에 `request_notice`(presentation 바텀시트 + `레스토랑 확인이 필요한 예약` 제목)와 `promo_interstitial`(`다음에 볼게요` 버튼) kind를 추가했다. dialog가 없을 때만 검사한다.
- `request_notice`는 `예약 신청` 클릭으로 자동 진행한다. 즉시 신청 제출이 아님은 사용자가 확인했고(2026-07-12), `다시 보지 않기`·`취소`는 건드리지 않는다.
- `promo_interstitial`은 `다음에 볼게요`만 클릭한다. `7일간 보지 않기`는 계정 표시 설정을 바꾸므로 누르지 않는다.
- 자동 진입 단계에서도 홍보 인터스티셜이 예약하기 클릭을 삼키면 닫고 예약하기를 다시 클릭한다 (`EntryAdapter.dismissPromo`, 오케스트레이터가 닫은 뒤 재클릭 허용).
- 자동화 경계 문서에 두 클릭을 명시했다.

## 검증

- 실패 테스트 4개 먼저 작성해 RED 확인 후 구현했다: 시트 분류·예약 신청 클릭, 인터스티셜 분류·닫기, entry 어댑터 닫기, 진입 루프 닫기 후 재클릭.
- `npm run check` 전체 통과 (166 tests + dist + independence).

## 남은 것

- `예약 신청` 클릭 이후 화면은 미실측이다. 다음 실전/테스트 런에서 기존 판정 규칙(알면 진행, 모르면 진단과 함께 인계)으로 관측된다.
- 두 화면 모두 이시즈에 단일 매장 실측이므로 다른 승인제 매장에서 재발 로그로 교차 확인한다.
