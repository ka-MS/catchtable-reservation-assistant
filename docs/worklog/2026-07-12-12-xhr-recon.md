# 2026-07-12-12 XHR 슬롯 정찰 (R1~R5) + 실오픈런 판독

## 방법

DevTools MCP(`use-chrome-devtools` 스킬)로 AI가 직접 수행. 이시즈에 탭에 `window.__recon`(PerformanceObserver + MutationObserver) 주입 → 예약 모달 열기 → 인접(14)/목표(15)/같은날짜(15 재클릭)/타 날짜(31·29) 클릭 시퀀스로 발사 조건·타이밍 계측. 응답 바디는 DevTools 네트워크 패널로 관측(직접 호출 없음). 텔레메트리 IndexedDB(`catchtable-reserve-telemetry`)를 사이드패널 오리진에서 직접 조회.

## 실측 결과 (site-behavior §8.1에 기록)

- **R1**: `POST ct-api.catchtable.co.kr/api/reservation/v1/dining/time-slots?shopRef=…` — 별도 API 호스트(Cloudflare). URL에 날짜 없음(헤더 `yymmdd`), 본문 암호화.
- **R2**: 날짜 셀 클릭마다 1회 발사, **같은 날짜 재클릭은 재발사 없음** → 인접 토글 필수(현행 전략 검증).
- **R3**: 클릭→발사 217~379ms(SPA 내부 지연) + 왕복 52~63ms + 렌더 56~182ms = **클릭→렌더 330~560ms**.
- **R5**: 가용 여부 무관 항상 200 + `timeSlotMap`. 도착 신호는 항상 발생.
- R4(격리 월드 가시성)만 잔여 — 구현 단계 확정.

## 실오픈런 판독 (run-e2c48fb6, 7/25 예약, 22:00 실제 오픈)

- 시계: 초기 boundary +1020(±185, 5/5 지지) / 최종 median +840(±531, 5표본에 틱 없음) — **표본 5 설정이라 최종이 median으로 떨어짐**. 표본 9 권장 재확인.
- 목표 클릭 −15/+260/+556/+843/+1152ms → 감지 **+1303ms**. 감지된 렌더는 +843 클릭의 응답(클릭→렌더 ~460ms, R3와 일치). **사이클 2~4의 비행 중 응답은 후속 토글 클릭이 밟아 소실.**
- 결론: 실오픈 병목 = ① 클릭→발사 SPA 지연(~250ms) + ② 토글 연타가 비행 중 렌더를 파괴. 관측(도착 신호)만으론 부족 — **콰이어스(비행 중 요청 완료까지 토글 보류)가 핵심**. 스펙 §3.1 개정.
