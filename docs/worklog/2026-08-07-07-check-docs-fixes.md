# 2026-08-07-07 문서 검사 결함 수정 (#26)

## 한 것

`scripts/check-docs.mjs`의 미탐 2건·오탐 2건을 고쳤다. 누락돼 있던
`SP-025/02`·`/03` 카탈로그 등록도 함께 넣었다.

## 내린 결정

**미탐 두 건을 한 번에 고쳤다.** 중첩 패키지 미순회(#26-2)와 부분 문자열
매칭(#26-1)은 증상이 다르지만 원인이 같다 — 카탈로그를 **텍스트로** 봤기
때문이다. 이제 카탈로그의 **링크 경로를 파싱해** 등록 집합을 만들고, `.md`를
직접 담은 디렉터리를 깊이 제한 없이 찾아 대조한다. 두 결함이 같이 사라진다.

**스킴을 열거하지 않는다.** `chrome:`·`about:`을 하나씩 추가하는 방식은
빠뜨린 스킴이 깨진 링크로 보고된다. URI 스킴 일반형(`^[a-z][a-z0-9+.-]*:`)과
프로토콜 상대(`//`)로 판정한다.

**코드 제거는 길이를 보존한다.** 펜스와 인라인 코드를 같은 길이의 공백으로
치환해 링크 정규식의 오프셋에 영향을 주지 않게 했다.

**#26의 5번(`.claude/skills` 제외)은 고치지 않았다.** 아래 참조.

## 검토했다 버린 선택지

- **정확 매칭(`=== name + "/"`)만 고치기** — 1번은 해결되지만 중첩 패키지는
  여전히 순회 대상이 아니다. 실제로 뚫려 있던 쪽은 2번이다.
- **최상위 + 한 단계만 순회** — `SP-011/T1/RT-15` 같은 3단 패키지가 있다.
  깊이 제한은 또 다른 미탐을 만든다.
- **`.claude/skills/**`를 파일 목록에 추가** — 무효다. 두 `SKILL.md`의
  마크다운 링크는 각각 0건이고 `docs/` 참조는 전부 백틱 인라인 코드다.
  추가해도 검사할 링크가 없고 위험도 그대로 남는다.
- **백틱 안의 경로까지 검사** — 5번의 바탕 우려를 실제로 잡으려면 이게
  필요하지만, 문서에서 `docs/`를 일반명사처럼 언급하는 경우가 흔해 오탐
  위험이 크다. 이 파일 헤더가 경고하는 "오탐이 나면 검사 전체가 무시된다"에
  정면으로 걸린다. **별도 판단 항목으로 분리한다.**

## 리뷰 반영

**상위 경로 자동등록을 제거했다.** 초안은 중첩 패키지의 상위 경로도 등록으로
쳤는데, 그러면 **자식만 카탈로그에 있고 부모가 미등록일 때 빠져나간다** —
이 PR이 고친 미탐의 축소판을 한 단계 안쪽에서 다시 여는 셈이다.

현재 45개 패키지가 전부 카탈로그 직접 링크로 등록돼 있어 그 루프에 기대는
패키지는 **0개**였다. 아무것도 사지 못하면서 검사만 느슨하게 만드는
코드였다(`AGENTS.md` §2).

**닫히지 않은 펜스 오탐은 남긴다.** 문서 끝까지 코드로 삼키게 고치면 그
뒤의 정상 링크가 통째로 검사에서 빠진다. CI 게이트에서는 시끄러운 오탐이
조용한 미탐보다 낫다는 판단이며, 근거를 코드 주석에 남겼다.

## 남은 것

`#26`의 5번은 미해결로 남긴다. 파일 목록 확장으로는 해결되지 않으며,
백틱 경로 검사는 성격이 다른 기능이다.

## 배운 것

미탐 2번이 **가정이 아니라 실제로 벌어져 있었다.** `SP-025/02`·`/03`이
미등록인 채 PR #25·#30의 CI가 두 번 `docs validation passed`를 찍었다.
내가 만든 검사가 내 누락을 못 잡은 것이다.

리뷰가 지적한 5건 중 하나(5번)는 **전제가 틀렸다.** "두 SKILL.md가 `docs/`로
링크한다"가 사실이 아니었고, 그래서 제안된 수정이 무효였다. 지적을 받으면
근거부터 재현한다 — 이번엔 그게 헛수고를 막았다.
