# 2026-07-10 재구축 작업 로그

## Phase 0 — 현 상태 확인

- Git은 `master`의 unborn 상태였고 모든 파일이 미추적이었다.
- 기존 상태를 잃지 않도록 `rebuild/open-run-mvp` 브랜치를 만들었다.
- `node_modules/`, `dist/`를 제외하고 `cb15c27`에 재구축 전 스냅샷을 보존했다.
- 기존 `npm test`는 7개 테스트가 통과했다. 하지만 실측과 다른 셀렉터 및 슬롯 이후 추측 흐름을 검증하므로 새 기준에서는 폐기 대상이다.

## Phase 2 — 자산 분류

- 현재 저장소 44개 파일을 KEEP / REVISE / DEPRECATE / DELETE로 분류했다.
- 상세 결과는 `docs/analysis/legacy-inventory.md`에 기록했다.
- 반복 금지 실패 원인은 `docs/analysis/legacy-review.md`에 고정했다.

## Phase 3 — 분석 자료 이관

- 달력 셀, 슬롯 칩, 날짜 토글, 서버 Date 헤더 실측만 `docs/analysis/site-behavior.md`로 재작성했다.
- 슬롯 이후 화면과 인원 선택 상태는 미실측으로 명시했다.
- 외부 실험 저장소 없이 이해할 수 있도록 출처 이력은 `source-migration-record.md` 하나로 제한했다.

## Phase 4 — 공식 기준 확정

- 제품 요구사항, UI 요구사항, 자동화 경계, 상태 머신, 아키텍처, 테스트 전략, 구현 계획을 작성했다.
- 무기한 pause를 제거하고 슬롯 클릭 직후 `HANDED_OFF`를 종료 상태로 확정했다.
- Chrome MV3, 날짜 토글, 서버 시계, on-demand 주입, 사용자 인계 결정을 ADR로 기록했다.

## Phase 5 — 기존 기준 폐기

- 과거 공식 문서 13개를 폐기 안내문으로 축약하고 대체 문서를 연결했다.
- 중복된 `docs/progress/`와 빈 phase 인덱스는 Git 이력에 남긴 뒤 제거했다.
- 일회성 외부 참조 메타프롬프트를 폐기해 현재 저장소의 공식 문서만 남겼다.

## Phase 6 — 깨끗한 구현 기반

- 실패한 `src/`와 테스트를 제거하고 MV3 스캐폴드를 새로 만들었다.
- manifest 상시 주입을 제거하고 Background/Content/Side Panel 경로를 분리했다.
- Node 기반 clean, dist 검증, 독립성 검증 스크립트를 추가했다.
- `npm run typecheck`, `npm test` 2개, `npm run check:dist`가 통과했다.

## Phase 7-1 — 공유 코어

- 한국어 시간 파싱, 로컬 datetime/epoch 변환, 오픈+10분 기본값과 설정 검증을 구현했다.
- 최소 RTT 표본군의 중앙값을 사용하는 서버 오프셋 계산을 구현했다.
- 문서 상태와 동일한 상태 머신, dry-run 클릭 상태 차단, 종료 상태 불변식을 구현했다.
- 테스트를 먼저 실패시킨 뒤 구현했고 전체 14개 테스트가 통과했다.

## Phase 7-2 — 실측 Site Adapter

- 출처 주석이 있는 달력·슬롯 fixture를 만들었다.
- 날짜 셀의 연·월·일, 선택·비활성 속성과 가장 가까운 인접 가용 날짜를 판독한다.
- 슬롯의 `data-busy`, `aria-hidden`, hidden, 복제 시간을 필터링한다.
- 우선순위 목록을 범위 내 이른 시각보다 먼저 적용한다.
- adapter 테스트를 먼저 실패시킨 뒤 구현했고 전체 20개 테스트가 통과했다.

## Phase 7-3 — 오픈런 오케스트레이터

- 중단 가능한 Scheduler와 같은 오리진 HEAD 시계 측정 adapter를 구현했다.
- T-3 대기, 날짜 토글, 25ms DOM 후보 확인, 우선순위 선택, dry-run, 실제 클릭 1회, 즉시 인계, 타임아웃을 구현했다.
- 가짜 Clock 통합 테스트로 시간 경과와 종료를 즉시 재현했다.
- 테스트를 먼저 실패시킨 뒤 구현했고 전체 28개 테스트가 통과했다.
