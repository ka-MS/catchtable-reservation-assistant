# 워크플로 가드레일

**날짜:** 2026-08-07
**세션:** 워크플로 지침 정비
**PR:** [#24](https://github.com/ka-MS/catchtable-reservation-assistant/pull/24)

## 한 것

- 워크로그가 2026-07-27 이후 끊긴 원인을 찾았다. 작성 요구가 `AGENTS.md`에
  없었고, recon 스킬과 개별 spec 패키지에만 있었다.
- 작업 지침이 7개 문서에 흩어져 있고 그중 `AGENTS.md`만
  `CLAUDE.md`의 `@import`로 매 세션 자동 로드된다는 점을 확인했다.
- `AGENTS.md` §7을 신설해 작업 유형별 산출물을 표로 넣고, 워크로그의
  성격(색인이지 보고서가 아님)을 정의했다.
- `scripts/check-docs.mjs`를 만들어 `npm run check`에 편입했다.
- 직전 세션(SP-025/01, SP-026)의 워크로그를 소급 작성했다.

## 결정

| 결정 | 근거 |
|---|---|
| 규칙은 `AGENTS.md`에, 세부 절차는 개별 문서에 | 자동 로드되는 문서에 없는 규칙은 존재하지 않는 것과 같다. 기준은 중요도가 아니라 "매번 필요한가"다 |
| 워크로그는 세션마다, 단 얇게 | 시간축 기록은 git log·HANDOFF·spec 어느 것도 대체하지 못한다. 다만 구현 세부·수치를 재기술하면 중복이 되고 반드시 어긋난다 |
| 문서 검사는 판정이 명확한 것만 | 오탐이 나면 검사 전체가 무시된다. 링크 유효성과 카탈로그 등록만 넣고 "수치가 최신인가"는 제외했다 |
| 워크로그 규칙을 이 PR에 즉시 적용 | 리뷰 지적. 규칙이 자기 자신에게 적용되지 않으면 도입 시점부터 예외가 생긴다 |

## 검토했다 버린 것

- **공통지침 허브 문서 신설** — `AGENTS.md` → 허브 → 개별 문서로 홉이
  늘면 중간에 따라가지 않을 확률만 늘어난다. 허브 자체가 자동 로드되지
  않아 지금 문제(안 읽는 문서에 규칙이 있음)를 반복한다.
  `docs/README.md`와 역할도 겹친다.
- **Claude Code `Stop` 훅으로 워크로그 미작성 경고** — 훅은 "작업이
  완료됐는지"를 판정할 수 없다. 매 응답마다 발화하면 소음이 되고
  곧 무시된다. 훅은 기계가 판정할 수 있는 것에만 쓴다.
- **워크로그 폐지** — spec `30`/`40`이 내용을 덮는다고 판단했으나
  틀렸다. 내용 축과 시간 축은 다르다. "8월 7일에 뭘 했나"에 답할 수
  있는 문서가 없어진다.
- **spec 있는 작업은 워크로그 면제** — 위와 같은 이유로 철회했다.
