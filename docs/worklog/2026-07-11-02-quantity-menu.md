# 2026-07-11 수량형 메뉴 지원 작업 로그

## 문제

돗가비누각 실행에서 테이블 타입 완료 뒤 `후속 예약 화면을 5초 안에 확인하지 못했습니다`로 인계됐다. 메뉴 선택 dialog가 checkbox 없이 수량 스테퍼로 구성돼 있어 adapter가 활성 선택지 0개(전환 중)로 오판하고 waiting만 반복했다.

## 실측 (돗가비누각)

- `input[type="number"][aria-label="<메뉴명> 수량"]`과 메뉴별 `수량 추가`/`수량 감소` 버튼(수량 0이면 감소 disabled)
- 진행 버튼(`다음`/`확인`)은 수량 미달이어도 DOM에서 항상 활성이며 클릭이 무시된다
- 필수 총수량 = 예약 인원수 (2명에서 수량 1은 진행 무시, 수량 2는 전환 성공)
- 인원수 초과 시 `예약 인원(N명) 보다 많이 선택할 수 없는 메뉴입니다` 안내

## 수정

`advanceMenu`를 checkbox 경로와 수량 경로로 분기했다. 수량 경로는:

1. 키워드 일치 메뉴(비어 있으면 첫 메뉴)를 대상으로 정한다.
2. 다른 메뉴 수량이 있으면 감소로 0까지 내린다 (checkbox 해제와 대칭).
3. 대상 수량이 인원수 미만이면 `수량 추가`를 1회씩 클릭한다 (1클릭-1액션 유지).
4. 인원수 도달 시에만 `다음`/`확인`을 클릭한다. 버튼이 활성이어도 미달이면 클릭하지 않는다.
5. 추가 버튼이 비활성인데 미달이면 인계한다.

`PostSlotConfig`에 `personCount`를 전달한다. 진행 버튼 상태 대기는 이 변형에서 신호가 아니므로 총수량 도달을 진행 조건으로 사용한다.

## 검증

- 실패 테스트 4개(인원수 채움, 키워드, 타 메뉴 해제, 추가 불가 중단)를 먼저 작성해 RED 확인 후 구현했다.
- `npm run check` 전체 통과.
