# 적대적 리뷰와 수정 결과

**리뷰일:** 2026-07-10  
**대상:** 오픈런 MVP 구현

## 수정 완료

| 심각도 | 발견사항 | 영향 | 수정과 회귀 검증 |
|---|---|---|---|
| 높음 | 연속 RUN_EVENT의 storage get/set이 병렬 실행될 수 있음 | 앞 상태·이벤트 유실 | `SerialTaskQueue`로 도착 순서 직렬화, 순서 회귀 테스트 추가 |
| 높음 | 목표 날짜 클릭 직후 인접 날짜의 오래된 슬롯 DOM을 읽을 수 있음 | 잘못된 날짜 슬롯 클릭 위험 | 목표 날짜 후 안정화 대기와 `targetSelected` 재검증 추가 |
| 중간 | 첫 상태 이벤트 전에 중지하면 active tab이 없을 수 있음 | 즉시 중지 실패 | START 전에 pending run과 tabId 저장 |
| 중간 | 실행 중 PANEL_START가 다시 들어오면 storage를 초기화할 수 있음 | 활성 실행 로그·상태 손실 | 비종료 activeRun 존재 시 중복 START 거부 |
| 중간 | 슬롯 selector가 페이지 전체 `button[data-busy]`를 검색 | 비예약 UI 오탐 가능성 | 실측 영역인 `main button[data-busy]`로 범위 제한 |
| 중간 | 감시 탭이 다른 경로로 이탈해도 Background 상태가 실행 중으로 남을 수 있음 | Side Panel 잠김·잘못된 활성 상태 | `tabs.onUpdated`에서 대상 매장 경로 이탈 시 `STOPPED` 정리 |
| 낮음 | 자동 계산된 stopAt을 재시작 후 직접 수정값으로 오인 | 다음 openAt 변경 시 +10분 갱신 안 됨 | `draftStopAtDirty`를 별도 저장·복원 |
| 낮음 | 날짜 안정화 대기 중 종료 시각 도달 시 dry-run 후보를 마지막으로 읽을 수 있음 | `TIMED_OUT` 대신 dry-run 완료 오판 | 후보 판독 전에 종료 시각 재검증 |

## 공격한 불변식

- dry-run은 어떤 슬롯도 클릭하지 않는다.
- 종료 상태에 들어간 런은 다시 전이하지 않는다.
- 감시 종료 시각 이후 날짜와 슬롯을 클릭하지 않는다.
- actual 실행은 슬롯을 최대 한 번 클릭하고 즉시 인계한다.
- 슬롯 이후 화면 텍스트와 버튼은 Content 번들에 존재하지 않는다.
- Content Script 주입 경로는 하나다.
- 이벤트 기록은 도착 순서를 보존한다.

## 잔여 위험

| 심각도 | 위험 | 현재 처리 |
|---|---|---|
| 중간 | 실제 사이트에서 새 빌드의 dry-run을 아직 수행하지 않음 | Chrome 재로드 후 수동 게이트로 남김 |
| 중간 | 인원 선택 상태의 안정 속성이 미실측 | 사용자 준비 확인 필수, 자동 검증·설정 없음 |
| 중간 | 목표 날짜 요청 완료를 증명하는 네트워크 연계 신호가 없음 | 목표 선택 안정화 후 DOM 감지, 첫 실사이트 dry-run에서 재검증 |
| 낮음 | 슬롯 클릭 이후 홀드·화면 전이가 미실측 | 클릭 직후 무조건 `HANDED_OFF` |
| 낮음 | 운영체제 알림 표시가 플랫폼 설정에 따라 차단될 수 있음 | Side Panel 상태와 toolbar 배지를 정본으로 유지 |

치명적 또는 높은 심각도의 미해결 코드 문제는 현재 확인되지 않았다. 실사이트 dry-run 미완료는 제품 완료 게이트로 남아 있다.
