# 기존 구현 부검

**검토일:** 2026-07-10  
**대상:** 재구축 전 스냅샷 `cb15c27`

기존 구현은 `npm test`에서 7개 테스트가 통과했지만 실사이트에서는 시작 직후 중단되거나 슬롯을 찾지 못했다. 테스트가 구현의 가정을 그대로 복제했기 때문에 실제 동작을 증명하지 못했다.

| 문제 | 직접 원인 | 새 기준의 방지책 |
|---|---|---|
| 예약 오픈 시각 부재 | `startTime`/`endTime`만 예약 시간으로 사용 | `openAtMs`와 희망 슬롯 범위를 별도 필드로 정의 |
| 슬롯을 찾지 못함 | 실사이트에 없는 `main button[aria-disabled]` 사용 | 실측된 `button[data-busy]`와 `aria-hidden` 필터만 adapter에 허용 |
| 대화상자 오판 | 실사이트 모달에 없는 `role="dialog"` 가정 | 슬롯 이후는 MVP 미실측 영역으로 즉시 `HANDED_OFF` |
| 시작 즉시 영구 중단 | 일시적 조건 불일치에도 observer를 끊는 `PAUSED_USER` | 무기한 pause 제거, 검증 실패는 `FAILED` 또는 명시적 재시작 |
| 중복 엔진 가능성 | manifest 상시 주입과 executeScript 폴백 병용 | background의 PING 후 on-demand 주입만 사용 |
| 재렌더 중복 클릭 | DOM 노드 `WeakSet`에만 의존 | 런 컨텍스트의 슬롯 시간 논리 키로 클릭 1회 보장 |
| 시간대 오류 위험 | ISO 문자열과 `datetime-local` 변환 혼용 | 모든 저장·비교는 epoch ms, UI 경계에서만 로컬 변환 |
| 무제한 재감시 | 재시도 수명주기가 종료 시각과 분리 | 모든 대기·토글은 `stopAtMs`와 AbortSignal로 강제 종료 |
| dry-run 안전성 부족 | 엔진 수준 클릭 차단 계약 부재 | 오케스트레이터가 dry-run에서 click 경로에 진입하지 않음 |
| 테스트의 초록불 착시 | 임의 DOM fixture로 추측 셀렉터 검증 | 실측 출처 주석이 있는 fixture만 사이트 adapter 테스트에 허용 |
| 슬롯 이후 범위 과장 | 테이블 타입·예약금·결제 화면을 추측 자동화 | 슬롯 클릭 직후 자동화 종료 및 사용자 인계 |
| 상태와 문서 불일치 | 구현 상태와 스펙 상태명이 다름 | 단일 `RunState`와 전이 표를 문서·코드·테스트에서 공유 |

## 폐기되는 성공 기준

- 추측 fixture에서 특정 버튼을 클릭하면 성공이라는 기준
- 슬롯 이후 테이블 타입 또는 예약금 확인까지 진행하면 성공이라는 기준
- `PAUSED_USER`가 안전한 정상 상태라는 기준
- 감시 시작 직후 현재 URL 파라미터가 완전히 일치해야 한다는 기준

## 새 회귀 게이트

- Content Script 번들에 정적 `import`가 없어야 한다.
- manifest에 `content_scripts`가 없어야 한다.
- 핵심 코드에 외부 실험 저장소 경로가 없어야 한다.
- dry-run에서 DOM click 호출은 0회여야 한다.
- 슬롯 선택 후 다음 DOM을 해석하거나 클릭하지 않아야 한다.
- 종료 시각 이후 스케줄러와 DOM 클릭이 발생하지 않아야 한다.
