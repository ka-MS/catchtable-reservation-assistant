# 00. 1차 어플리케이션 목표와 실행 워크플로우

## 문서 역할

이 문서는 Catchtable Reserve Assistant의 1차 어플리케이션을 완성하기 위한 최상위 실행 지시서다. 이후 작업은 이 문서의 최종 목표, 단계별 통과 기준, 비범위를 따른다.

기능 상세 기준은 [01-reservation-automation-spec.md](01-reservation-automation-spec.md)에 두고, 단계별 분석·설계·검증 결과는 이 디렉터리에 추가한다.

## 최종 목표

사용자가 Chrome에서 캐치테이블에 직접 로그인한 뒤, 하나의 확인된 예약 플로우에서 예약 조건을 설정하고 감시를 시작하면, 확장 프로그램이 조건과 일치하는 예약 가능 UI를 감지해 중복 없이 즉시 다음 단계로 진행하고 결과를 명확히 보여주는 1차 Chrome 확장 프로그램을 완성한다.

이 목표는 실제 예약 페이지에서 검증된 하나의 세로 흐름을 제공하는 것을 뜻한다. 여러 식당 유형, 모든 캐치테이블 화면, 서버 대기열 우회를 한 번에 해결하는 것을 뜻하지 않는다.

## 완료 정의

다음 조건을 모두 만족해야 1차 어플리케이션이 완료다.

1. Chrome 개발자 모드에서 확장 프로그램을 로드할 수 있다.
2. Side Panel에서 식당 URL, 인원, 날짜, 희망 시간 범위를 설정하고 감시를 시작·중지할 수 있다.
3. 확인된 실제 캐치테이블 예약 플로우에서 날짜·인원·시간 슬롯을 읽고 조건 일치 여부를 판정한다.
4. 일치하는 슬롯이 렌더링되면 같은 슬롯을 한 번만 클릭한다.
5. 클릭 후 성공, 슬롯 소진/실패, 로그인 필요, CAPTCHA/결제/수수료 확인 필요 상태를 구분해 표시한다.
6. 슬롯이 소진되거나 일시적 UI 실패가 발생하면 사용자 중지 또는 종료 시각까지 상태 기반 재시도를 유지한다.
7. 로그인, CAPTCHA, 결제 또는 수수료 동의는 자동 처리하지 않고 사용자에게 제어권을 넘긴다.
8. 모의 DOM과 실제 페이지에서 핵심 흐름을 검증하고, 조건 일치 DOM 변경부터 클릭 호출까지의 로컬 p95 측정값을 기록한다. 목표는 50ms 이하이다.
9. 적대적 리뷰에서 확인된 치명적·높은 심각도의 문제를 수정하고 영향을 받는 검증을 다시 통과시킨다.

## 고정 제약

- Chrome Extension Manifest V3
- TypeScript + 순수 HTML/CSS/JavaScript
- React, UI 프레임워크, 외부 런타임 라이브러리, 서버, 데스크톱 제어 앱 제외
- `document_start` Content Script와 `MutationObserver` 중심의 DOM 감시
- 사용자의 기존 로그인 세션과 정상 페이지 UI만 사용
- 비밀번호, 쿠키, 결제정보를 읽거나 저장하지 않음
- CAPTCHA, 접속 대기열, 비공개 API 우회 금지
- 다수 계정, 다수 탭, 예약권 재판매 기능 제외

## 동적 워크플로우

```text
분석 -> 설계 -> 구현 -> 검증 -> 적대적 리뷰·수정
  ^       ^         |        |              |
  +-------+---------+--------+--------------+
          발견된 사실이나 실패 원인에 따라 필요한 단계로 되돌아감
```

단계는 선형 체크리스트가 아니다. 구현, 검증, 리뷰에서 새 사실이 발견되면 해당 사실을 먼저 분석 문서에 기록하고 설계·구현을 갱신한 뒤 다시 검증한다. 통과 기준이 충족되지 않은 단계는 다음 단계 완료로 선언하지 않는다.

## 단계 실행 규칙

### 1. 분석

- 실제 캐치테이블 예약 페이지를 기준으로 URL, SPA 전환, 날짜·인원·시간 슬롯, 예약 가능/불가, 사용자 확인 화면을 관찰한다.
- DOM 구조를 모르는 상태에서 선택자나 클릭 순서를 구현하지 않는다.
- 확인할 수 없는 사실은 가정으로 숨기지 않고 `미확인`으로 기록한다.

### 2. 설계

- Content Script, Service Worker, Side Panel의 책임과 메시지 계약을 최소 범위로 정한다.
- 정상 흐름뿐 아니라 슬롯 재렌더링, 클릭 후 슬롯 소진, 로그인 만료, 사용자 중지, SPA 화면 전환을 다룬다.
- 단일 실제 플로우가 확인되기 전에는 다중 사이트/다중 플로우 추상화를 만들지 않는다.

### 3. 구현

- 분석과 설계에서 확인된 단일 흐름만 구현한다.
- 클릭 직전까지의 판정은 Content Script 안에서 끝내며, Service Worker 왕복을 기다리지 않는다.
- 중복 클릭 방지와 결과 검증을 클릭 코드와 같은 작업 단위로 구현한다.
- 각 변경 뒤 TypeScript 검사를 실행한다.

### 4. 검증

- 모의 DOM으로 조건 감지, 단일 클릭, 성공/실패/사용자 확인 필요 상태를 재현한다.
- 실제 페이지에서 지원 범위의 흐름을 수동으로 확인한다.
- 성능 기록은 `performance.now()`를 기준으로 DOM 감지와 클릭 호출 시점의 차이를 남긴다.
- 검증 실패는 원인에 따라 분석, 설계 또는 구현 단계로 되돌린다.

### 5. 적대적 리뷰·수정

다음 관점에서 코드와 동작을 검토한다.

- DOM이 다시 렌더링되거나 슬롯 노드가 교체될 때 중복 클릭하는가
- SPA 이동, 탭 새로고침, Service Worker 재기동 뒤 상태가 잘못 복구되는가
- 페이지 로딩 중이거나 조건 UI가 아직 완성되지 않았는데 클릭하는가
- 사용자가 중지한 직후에도 예정된 동작이 이어지는가
- 슬롯 소진, 로그인 만료, CAPTCHA, 결제/수수료 확인에서 잘못 계속 진행하는가
- `chrome.storage` 쓰기나 메시지 왕복이 감지·클릭 경로를 늦추는가
- 실제 DOM 선택자가 모의 화면에만 맞거나 너무 넓게 매칭되는가

발견사항은 심각도와 재현 절차를 기록한다. 수정 후에는 해당 실패를 재현한 검증을 다시 실행한다.

## 진행 상태 관리

- 단계별 산출물은 `docs/specs/`에 저장한다.
- 현재 위치와 바로 다음 작업은 `docs/08-status.md`에 짧게 반영한다.
- 되돌리기 어려운 기술 결정은 `docs/06-decisions.md`에 ADR로 남긴다.
- 병렬 작업이 필요하면 각 작업자는 `docs/progress/active/`에서 자기 진행 기록만 갱신한다.
