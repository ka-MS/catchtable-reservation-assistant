# 최종 목표와 개발 흐름

## 최종 목표

현재 저장소만으로 문서 확인, 빌드, 테스트, Chrome 로드, dry-run,
통제된 실제 실행과 유지보수가 가능한 예약 자동화 확장을 제공한다.

확장은 식당·날짜·인원을 준비하고 예약 오픈 시각에 목표 슬롯을
선택한다. 예약 완주를 명시적으로 켠 수동 실행에서는 실측된
필수 입력·필수 약관과 CatchPay 경로를 처리하고, 성공 후조건을 모두
확인한 경우에만 `COMPLETED`로 종료한다.

## 개발 흐름

```text
분석 → 설계 → 구현 → 검증 → 적대적 리뷰·수정
  ↑       ↑         │        │              │
  └───────┴─────────┴────────┴──────────────┘
```

- 분석: 현재 코드, 기존 기록과 실사이트 근거를 대조한다.
- 설계: 제품 경계, 상태, 책임, secret과 실패 정책을 확정한다.
- 구현: 실패 테스트를 먼저 추가하고 필요한 최소 코드를 작성한다.
- 검증: typecheck, 단위·fixture·dist·독립성 검사와 필요한 Chrome
  E2E를 수행한다.
- 적대적 리뷰: 중복 실행·결제, stale intent, 종료 경쟁, secret
  유출과 성공 오판을 우선 공격한다.

새 사이트 사실이 나오면 `docs/analysis/site-behavior.md`와 해당 spec의
분석을 먼저 갱신한 뒤 설계·테스트·코드에 반영한다.

## 단계 전환

새 개발 단계 전 `docs/worklog/HANDOFF.md`를 확인한다. 명시된
blocking backlog가 없으면 다른 non-blocking backlog 때문에 진행을
중단하지 않는다.

기능별 패키지는 필요한 범위에서 다음 문서를 가진다.

```text
00-index → 10-analysis → 20-design → 30-implementation
         → 40-verification → 50-adversarial-review
```

작은 UI·문서 변경은 불필요한 빈 단계를 만들지 않고 설계·검증 문서
하나로 끝낼 수 있다.

## 공통 완료 조건

- 자동화 경계와 실측 범위를 벗어난 DOM 조작이 없다.
- dry-run의 슬롯 click은 0회다.
- actual 실행의 슬롯·outer submit·PIN submit claim은 각 계약에서
  정한 최대 횟수를 넘지 않는다.
- 종료 시각과 사용자 중지 뒤 새 동작을 시작하지 않는다.
- 결과 불명 상태를 성공으로 만들거나 자동 재제출하지 않는다.
- raw PIN과 민감한 폼 값이 저장소·로그·진단에 남지 않는다.
- `npm run check`와 `git diff --check`가 통과한다.
- 실사이트 동작 변경은 통제된 Chrome 증거와 회귀 테스트를 남긴다.
