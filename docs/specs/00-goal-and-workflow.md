# 최종 목표와 동적 워크플로우

## 최종 목표

현재 저장소 하나만으로 문서 확인, 빌드, 테스트, Chrome 로드, dry-run, 유지보수가 가능한 오픈런 예약 MVP를 제공한다.

MVP는 예약 오픈 시각에 날짜 토글로 슬롯을 갱신하고 목표 슬롯을 감지한다. dry-run은 클릭하지 않고 종료하며 실제 실행은 슬롯을 한 번 클릭한 직후 사용자에게 인계한다.

## 워크플로우

```text
분석 -> 설계 -> 구현 -> 검증 -> 적대적 리뷰·수정
  ^       ^         |        |              |
  +-------+---------+--------+--------------+
```

- 분석: 기존 자산 분류와 실사이트 근거 확정
- 설계: 제품, 경계, 상태 머신, 아키텍처, 테스트 기준 확정
- 구현: 테스트를 먼저 실패시킨 뒤 최소 코드 구현
- 검증: typecheck, 단위·fixture 통합, dist, 독립성, 실사이트 dry-run
- 적대적 리뷰: 중복 실행, 종료 경쟁, storage 경합, 잘못된 날짜·슬롯 클릭을 우선 공격

새 사실이 나오면 해당 분석 문서를 먼저 고치고 영향을 받는 설계·코드·테스트를 다시 검증한다.

## 완료 조건

- 기존 자산 분류와 폐기 이유가 Git 이력과 문서에 남아 있다.
- 예약 오픈 일시 중심 UI와 `오픈+10분` 기본 종료가 구현돼 있다.
- 서버 시계, 상태 머신, Scheduler, Site Adapter가 분리돼 있다.
- on-demand Content Script 단일 주입만 사용한다.
- dry-run click 0회와 actual click 1회 후 인계가 테스트된다.
- 종료 시각 이후 토글·클릭이 없다.
- `npm run check`가 통과한다.
- 새 `dist/`를 Chrome에서 재로드한 뒤 실사이트 dry-run 체크리스트가 통과한다.
- 적대적 리뷰의 치명적·높은 심각도 미해결 문제가 없다.

## 현재 제한

실사이트 슬롯 클릭은 사용자의 예약 자리를 점유할 수 있어 자동 검증하지 않는다. 슬롯 이후 화면과 인원 선택 상태가 추가 실측되기 전까지 자동화 범위를 확장하지 않는다.
