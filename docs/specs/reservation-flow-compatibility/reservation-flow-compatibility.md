# 예약 흐름 호환성 안정화

## 배경

2026-07-14 실제 흐름에서 신형 Mobiscroll 달력을 기존 Adapter가 인식하지 못했고, 이로 인해 RT-07 복합 좌석·메뉴 흐름과 비스트로 꼬꼬뜨 결제 방식 흐름의 실제 폼 도착 검증이 막혔다.

## 하위 패키지와 순서

| 순서 | 패키지 | 목표 | 상태 |
|---|---|---|---|
| 01 | `calendar-dom-compatibility` | 구형 aria·신형 Mobiscroll 달력 동시 지원 | 구현·자동 검증·실 DOM 판독·장거리 월 이동 보강 완료 |
| 02 | `payment-method-auto-advance` | 결제 방식 자동 진행 설정과 확인 인터스티셜 지원 | 구현·자동 검증·실제 폼 인계 완료 |
| 03 | `seating-menu-live-validation` | RT-07 첫 활성 조합과 실제 흐름 검증 | 구현·자동 검증·실제 폼 인계 완료 |
| 04 | `live-form-e2e-verification` | 대표 식당의 실제 예약 폼 도착 검증 | 비드라이런 대표 식당 2곳 검증 완료 |

의존 순서는 `01 → 02 → 03 → 04`다. 비차단 미실측이 생기면 다음 패키지의 자동 테스트와 문서 작업은 계속한다.

## 범위

- EntryAdapter와 CalendarAdapter의 공유 달력 판독 계약
- 결제 방식 자동 진행 하위 설정, 저장 데이터 호환과 Side Panel UX
- 예약금 0원 전용 또는 사이트에서 이미 선택된 결제 방식 허용 정책
- RT-07 복합 좌석·메뉴 첫 활성 조합 검증
- dry-run이 아닌 실제 모드의 예약 폼 도착 검증

## 제외 범위

- 빈 모달 일반 재진입, 인증·대기열 복구, 무한 재시도
- 예약 폼 입력, 약관 동의, 결제 승인, 최종 예약 확정

빈 모달 복구는 `docs/plans/next-development.md`의 RT-11로 인계한다.

## 완료 기준

- 구형·신형 달력 fixture와 실제 달력 진입 검증
- 결제 방식 설정 기본값·상위 비활성화·구버전 저장 호환 검증
- 결제 방식 확인 인터스티셜 fixture 검증
- RT-07 첫 활성 조합과 별도 테이블/메뉴 회귀 검증
- 가능한 대표 식당의 `/ct/reservation/form` 도착과 `HANDED_OFF` 확인
- 전체 `npm run check`, `git diff --check`, 적대적 리뷰 통과

## 실제 검증 결과

- 01: 야키토리묵 실페이지의 Mobiscroll 활성 월 42셀에서 `2026-07-23` 선택 상태와 `2026-07-22` 인접 날짜를 판독했다. 전체 게이트는 269/269를 통과했다.
- 01 장거리 이동: 뽈뽀 실패 실행에서 최초 월 이동 클릭 유실 뒤 재시도가 없던 원인을 확인했다. 동일 월이 750ms 유지될 때 최대 3회 재시도하며, 실제 달력의 7월 -> 8월 -> 9월 정상 전환도 확인했다.
- 02: 비스트로 꼬꼬뜨 비드라이런에서 2026-07-31 18:00 홀 선택 후 예약 폼까지 도착해 `HANDED_OFF` 됐다. 34 events, dropped 0이며 최종 예약 버튼은 클릭하지 않았다.
- 02 정책 UX: 결제 자동 진행이 켜진 경우 `예약금 0원 방식만`과 `사이트에서 선택된 방식 허용`을 선택할 수 있다. 구버전 설정은 기존 동작을 보존하는 `selected_allowed`로 복원하며, 선택되지 않은 유료 방식은 어느 정책에서도 임의 선택하지 않는다.
- 03: 야키토리묵 비드라이런에서 첫 활성 좌석·메뉴 조합을 선택하고 `다음`을 정확히 한 번 클릭했다. 이어 `결제 방식 선택`과 예약금 0원 자동결제 안내를 통과해 예약 폼에서 인계했다.
- 04: 비스트로 꼬꼬뜨와 야키토리묵 모두 `/ct/reservation/form` 도착과 `HANDED_OFF`를 확인했다. 야키토리묵 최종 런은 31 events, 연속 seq 1~31, dropped 0이며 폼 예약 정보는 2026-07-23 17:00, 2명, 테이블과 일치했다.
- 최종 게이트: `npm run check` 282/282, dist 검증, 모듈 독립성 검증, `git diff --check`를 통과했다.
