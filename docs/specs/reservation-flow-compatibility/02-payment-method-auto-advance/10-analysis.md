# 02 결제 방식 자동 진행 분석

상태: 완료

## 현행 흐름

- `postSlotEnabled`는 테이블·메뉴·추가 상품·예약금 단계를 한꺼번에 제어한다.
- `PostSlotAdapter.advanceDeposit()`은 예약금 0원 radio가 있을 때만 선택·진행하고, 유료 방식만 있으면 인계한다.
- 비스트로 꼬꼬뜨에서 0원 자동결제 방식을 선택한 뒤 `이 방식으로 예약` 인터스티셜이 나타나지만 현재 판별기는 이를 `unknown`으로 처리한다.
- Side Panel, draft, 최근 설정, 즐겨찾기, 예약 작업은 모두 `ReservationConfig` 전체를 저장하므로 새 설정의 기본값과 구버전 복원이 함께 필요하다.

## 요구 계약

1. `결제 방식까지 자동 진행`은 `후속 선택 자동 진행`의 하위 설정이며 기본값은 켜짐이다.
2. 상위 설정이 꺼지면 테이블, 메뉴, 결제 설정 모두 비활성화하되 하위 값은 보존한다.
3. 결제 설정이 꺼지면 앞선 후속 단계는 진행하고 결제 방식 화면에서 인계한다.
4. 켜짐이면 `예약금 0원 방식만`과 `사이트에서 선택된 방식 허용` 중 정책을 선택할 수 있다.
5. `예약금 0원 방식만`은 0원 방식이 없으면 인계한다.
6. `사이트에서 선택된 방식 허용`은 0원 방식을 우선하고, 없으면 이미 선택된 활성 방식만 확인한다. 선택되지 않은 유료 방식을 임의 선택하지 않는다.
7. `이 방식으로 예약` 인터스티셜은 0원 자동결제 문구와 CTA를 함께 확인한 경우에만 진행한다.
8. `/ct/reservation/form` 도착 후에는 기존과 같이 인계하며 폼 입력·약관·최종 예약은 자동화하지 않는다.

## 영향 범위

- `ReservationConfig`, 검증 및 구버전 저장 정규화
- Side Panel 폼·draft·요약·종속 비활성화
- 최근 설정·즐겨찾기·예약 작업 복원
- post-slot 판별·행동 및 fixture 테스트
- 빌드 회귀와 실제 비스트로 꼬꼬뜨 흐름
