# 03 RT-07 복합 좌석·메뉴 실제 검증 설계

상태: 완료

## 선택 정책

결합 화면을 별도 테이블·메뉴 단계로 분해하지 않는다. 각 checkbox의 카드 heading을 좌석 증거로, aria-label과 heading을 메뉴 증거로 사용한다.

| 테이블 설정 | 메뉴 키워드 | 선택 |
|---|---|---|
| 아무거나 | 비움 | 기존 활성 선택, 없으면 첫 활성 항목 |
| 홀 | 선택 | heading에 `홀` 또는 `테이블`이 포함된 첫 일치 항목 |
| 바 | 선택 | heading에 `바` 또는 `카운터`가 포함된 첫 일치 항목 |
| 룸 | 선택 | heading에 `룸`이 포함된 첫 일치 항목 |
| 임의 | 입력 | 좌석 조건과 키워드를 모두 만족하는 첫 항목 |

## 안전 경계

- hidden 또는 disabled checkbox는 후보에서 제외한다.
- 일치 항목이 없으면 임의 대체하지 않고 인계한다.
- 다른 항목이 이미 선택됐다면 먼저 해제하고 다음 관측 주기에 목표 항목을 선택한다.
- 목표가 선택된 상태에서만 `다음` 또는 구형 `확인`을 클릭한다.
- 동일한 진행 버튼 노드는 한 번만 클릭하고 화면 전환을 기다린다.
- 이 단계 이후에도 예약 폼에서 약관·최종 예약을 자동화하지 않는다.

## 검증 방식

- 기존 실측 fixture에 `any + 빈 키워드` 테스트를 추가한다.
- 기존 bar/hall/room 및 별도 table/menu 테스트를 함께 실행한다.
- 실제 야키토리묵은 `dryRun=false` 예약 작업으로 수행하고 IndexedDB Trace의 `seating_menu` 판별·행동과 최종 상태를 기록한다.
- 선택 전 fixture와 선택 후 총 결제금액 fixture를 분리해 양쪽 화면을 고정한다.
