# 03 RT-07 복합 좌석·메뉴 실제 검증 분석

상태: 완료

## 현행 구현

- 야키토리묵 실측 화면은 `role="presentation"` Drawer 안에서 checkbox 하나가 좌석과 필수 메뉴를 함께 결정한다.
- `inspectPostSlot()`은 필수 메뉴 안내 또는 선택 후 총 결제금액 요약, 복수 선택 카드, 진행 버튼을 함께 확인해 `seating_menu`로 판별한다.
- `advanceSeatingMenu()`는 disabled/hidden 선택지를 제외한 뒤 좌석 설정과 메뉴 키워드를 함께 적용한다.
- 좌석이 `any`이고 메뉴 키워드가 비어 있으면 기존 선택을 우선하고, 없으면 첫 활성 조합을 선택한다.
- 별도 테이블 타입 dialog와 별도 메뉴 dialog는 기존 `table_type`, `menu` 경로를 유지한다.

## 확인된 공백

- `bar + 메뉴 키워드`, `hall`, 미지원 `room` 테스트는 있으나 `any + 빈 메뉴 키워드`의 첫 활성 조합 정책을 직접 고정한 테스트가 없다.
- 최초 fixture는 진행 버튼을 `확인`으로 기록했지만 2026-07-14 재실측 화면은 `다음`을 사용했다.
- 선택 직후 필수 메뉴 안내가 사라지고 총 결제금액 요약이 나타나므로, 안내 문구 하나만 보면 선택 완료 화면을 놓친다.
- 진행 클릭 뒤 같은 DOM을 한 주기 더 관측할 수 있어 중복 클릭 방지가 필요하다.

## 성공 기준

1. `any + 빈 메뉴 키워드`는 첫 활성 결합 항목을 선택한다.
2. 선택 후 같은 화면을 다시 판독하면 `확인`만 한 번 클릭한다.
3. 기존 bar/hall/room, 별도 table/menu 회귀 테스트가 유지된다.
4. 실제 야키토리묵에서 결합 단계의 판별·선택 이벤트를 확인하고 최종 예약 전에 인계한다.
