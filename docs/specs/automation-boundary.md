# 자동화 경계와 사용자 인계

2026-07-23에 종전의 "예약을 완료하지 않는다" 원칙을 폐기했고,
2026-07-27에 실측된 CatchPay 경로의 예약 완주 구현과 검증을
완료했다. 예약 완주는 사용자 opt-in이며, 아래 경계를 벗어나면
최종 제출하지 않고 `HANDED_OFF`로 종료한다.

## 자동화가 수행하는 일

- 같은 오리진 매장 URL의 서버 시간 측정
- 설정한 매장 상세 URL로 활성 탭 이동, dock 예약 CTA 클릭, 목표 월·날짜·인원 준비
- 실측된 달력 셀 판독과 인접 날짜/목표 날짜 클릭
- 실측된 슬롯 칩 판독, 시간 정규화, 우선순위 선택
- dry-run 결과 기록
- dry-run이 아닐 때 선택된 슬롯의 단일 클릭
- 후속 선택 자동 진행을 켠 경우에만 테이블 타입, 메뉴와 `예약금 안내`를 처리
- 결제 방식 자동 진행을 켠 경우에만 설정한 `zero_only | selected_allowed` 정책으로 현재 결제 방식 화면을 진행
- 수량형 필수 메뉴는 키워드 일치 메뉴(비어 있으면 첫 메뉴)의 수량을 예약 인원수까지만 설정 (메뉴 단가가 예약금인 식당은 수량만큼 보증금이 커진다)
- 예약 폼을 덮는 홍보 안내는 `확인했어요` 버튼만 눌러 닫는다 (안내 확인일 뿐 결제·응모 조작이 아니다)
- 매장 화면의 홍보 인터스티셜은 `다음에 볼게요` 버튼만 눌러 닫는다 (`7일간 보지 않기`는 누르지 않아 계정 표시 설정을 바꾸지 않는다)
- 승인제 매장의 `레스토랑 확인이 필요한 예약` 안내에서 `예약 신청` 버튼을 클릭해 진행한다 (즉시 신청 제출이 아님을 사용자가 확인했다. 2026-07-12. `다시 보지 않기`는 건드리지 않는다)
- 추가 상품 화면에서는 상품 수량을 변경하지 않고 활성화된 `다음`만 클릭
- 예약 완주 opt-in에서 비어 있는 필수 입력과 필수 약관만 처리
- 유일하게 판정된 CatchPay 선택과 일반결제 미선택 상태 재검증
- 사용자 결제금액 상한 안에서 outer submit과 필요한 PIN submit을 각각 최대 한 번 dispatch
- 성공 path·정확한 완료 문구·동일 예약 방문예정 일치 뒤 `COMPLETED` 확정

## 자동화가 수행하지 않는 일

- 로그인 정보 입력
- CAPTCHA 또는 대기열 우회
- 설정과 다른 인원 선택 또는 목표 인원 대체
- 추가 상품의 수량 증가·감소 조작
- 일반결제 또는 실측되지 않은 CatchPay 미등록 화면 조작
- 선택 약관 동의
- 저장된 PIN을 사용한 유료 예약 작업 실행
- 결과 불명·잘못된 PIN·닫힌 PIN 화면의 자동 재시도
- 예약 자동 취소

## 사용자 인계 조건

완주 목표에서도 다음 조건에서는 `HANDED_OFF`로 전환한다. (자동화가 완주를 이어갈 수 없는 지점만 남긴다.)

1. 로그인·CAPTCHA·대기열 등 자동화하지 않는 인증 화면을 만난 경우
2. 후속 선택 자동 진행이 꺼진 상태에서 슬롯을 선택한 경우
3. 활성 선택지가 있는데 설정한 테이블 타입 또는 메뉴와 일치하지 않는 경우 (전환 중 일괄 비활성 상태는 제한 시간 안에서 재시도)
4. 실측되지 않아 안전하게 조작할 수 없는 알 수 없는 중간 화면인 경우
5. 예약 CTA, 목표 월·날짜·인원을 제한 시간 안에 준비할 수 없는 경우
6. 실측된 달력·슬롯 상태 어느 것으로도 판정할 수 없는 화면인 경우
7. 예약 완주가 꺼져 있거나 매장·예약 요약·금액·CatchPay 검증이 일치하지 않는 경우
8. 유료 실행에 일회성 PIN이 없거나 PIN 화면·제출 결과가 불명확한 경우

인계 시 자동화는 모든 타이머와 observer를 정리하고 다시 개입하지 않는다. 사용자가 새 실행을 시작해야만 새로운 RunContext가 만들어진다.

## 최종 동작 안전 규칙

- 예약 완주 opt-in의 목표 종료 상태는 예약 확정(`COMPLETED`)이며, 실측된 CatchPay 흐름에서만 최종 제출한다.
- 결제·최종 확정을 자동화하므로, 잘못된 슬롯·인원·매장으로 진행할 경우 실제 예약금이 결제될 수 있다. 설정 검증과 실측된 화면 판정을 통과한 경우에만 완주한다.
- 실측되지 않은 화면·결제 수단은 조작하지 않고 `HANDED_OFF`로 넘긴다.
- claim 뒤 결과를 확인하지 못하면 성공이나 실패로 단정하지 않고 재제출 없이 `HANDED_OFF`로 넘긴다.
- CatchPay PIN은 수동 실행의 일회성 authorization으로만 받고 영속 저장하지 않는다.
- 실제 슬롯·중간 단계·완주 검증은 사용자가 지정한 테스트 예약 흐름에서만 수행한다.

## 실패와 재시도

- 무기한 pause 상태는 없다.
- 네트워크 시계 측정은 제한된 표본 수와 재측정 횟수만 사용한다.
- 날짜 토글은 감시 종료 시각까지만 반복한다.
- DOM click 실패는 같은 슬롯을 무한 재클릭하지 않고, 논리 슬롯 키를 기록한 뒤 제한된 다음 토글로 진행한다.
- 종료 시각에 도달하면 반드시 `TIMED_OUT`으로 종료한다.
