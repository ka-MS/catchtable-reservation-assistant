# 예약 자동화 제품 요구사항

## 1. 제품 정의

설정한 Catchtable 매장으로 이동해 예약창·날짜·인원을 준비하고,
예약 오픈 시각에 목표 시간 슬롯을 선택하는 개인용 Chrome MV3 확장
프로그램이다.

사용자가 예약 완주를 명시적으로 켠 수동 실행에서는 실측된 예약 폼의
필수 입력·필수 약관과 이미 선택된 CatchPay 경로를 진행한다. 매장·
날짜·시간·인원·금액과 성공 후조건을 모두 확인한 경우에만 예약 확정
상태 `COMPLETED`를 기록한다.

## 2. 제품 범위

- 단일 매장, 단일 탭, 단일 예약 날짜
- 자동 페이지 준비 또는 사용자가 준비한 예약 모달 사용
- 서버 시계 보정과 오픈 전 날짜 토글
- 우선순위·허용 범위에 따른 슬롯 선택
- 슬롯을 클릭하지 않는 dry-run
- 테이블, 메뉴, 추가 상품, 예약금 안내와 결제 방식 처리
- opt-in 예약 폼 완주와 CatchPay 결제
- 저장 설정, 즐겨찾기와 예약 작업 자동 실행
- 실행 telemetry, CSV와 실패 진단 bundle
- 사용자 중지와 감시 종료 시각에 따른 확정적 종료

## 3. 사용자 설정

| 필드 | 필수 | 규칙 |
|---|---|---|
| 식당 URL | 예 | `https://app.catchtable.co.kr/ct/shop/<slug>` |
| 예약 페이지 준비 | 예 | `auto` 또는 `prepared` |
| 예약 오픈 일시 | 예 | 로컬 UI 입력을 epoch ms로 저장 |
| 예약 날짜·인원 | 예 | `YYYY-MM-DD`, 1~20명 |
| 희망 시간 범위 | 예 | 분 단위, 경계 포함 |
| 시간 우선순위 | 아니오 | 허용 범위의 `HH:MM` 목록 |
| 후속 선택 자동 진행 | 예 | 끄면 슬롯 후속 화면에서 인계 |
| 결제 방식 자동 진행 | 예 | 끄면 결제 방식 화면에서 인계 |
| 결제 방식 정책 | 예 | `zero_only` 또는 `selected_allowed` |
| 테이블·메뉴 조건 | 아니오 | 일치하지 않으면 임의 대체 금지 |
| 감시 종료 시각 | 예 | 기본 `openAt + 10분` |
| dry-run | 예 | 켜면 슬롯 click 0회 |
| XHR 응답 모드 | 예 | `off`, `observe`, `empty_exit` |
| 예약 완주 | 예 | 기본 false, 수동 opt-in |
| 최대 결제금액 | 완주 시 | 0~500,000원 정수 상한 |
| 필수 입력 기본 답변 | 아니오 | 비어 있는 필수 텍스트 입력에만 사용 |

신규 폼의 XHR 응답 모드는 `empty_exit`이다. 구 저장값에 모드가
없으면 안전한 호환 기본값 `off`로 복원하고, legacy
`availabilityProbeEnabled=true`는 `observe`로 변환한다.

CatchPay PIN은 `ReservationConfig`가 아니다. 유료 완주가 필요한
수동 실행에서만 4자리 일회성 authorization으로 전달하고 입력 직후
Side Panel에서 비운다. draft, history, favorites, scheduled job,
storage, telemetry와 diagnostic에는 저장하지 않는다.

## 4. 실행 흐름

1. 설정을 검증하고 논리 실행과 첫 attempt를 만든다.
2. 필요하면 목표 매장으로 이동하고 예약창·날짜·인원을 준비한다.
3. 같은 오리진 서버 시계를 측정하고 오픈 전 대기한다.
4. 인접 날짜와 목표 날짜를 토글하며 슬롯을 찾는다.
5. 허용 범위와 우선순위에 맞는 슬롯을 DOM에서 재검증한다.
6. dry-run이면 클릭 없이 `DRY_RUN_COMPLETED`로 종료한다.
7. actual 실행이면 슬롯을 한 번 dispatch하고 후속 화면을 확인한다.
8. 허용된 테이블·메뉴·추가 상품·예약금·결제 방식 단계를 처리한다.
9. 완주가 꺼져 있으면 예약 폼에서 `HANDED_OFF`로 종료한다.
10. 완주가 켜져 있으면 매장·예약 요약·금액·CatchPay를 다시
    검증하고 필수 입력과 필수 약관만 처리한다.
11. outer submit과 필요한 PIN submit을 phase별 durable claim 뒤
    최대 한 번 dispatch한다.
12. 성공 path, 정확한 완료 문구와 동일 예약의 방문예정 항목이 모두
    일치할 때만 `COMPLETED`로 종료한다.

준비 정체는 `RunSupervisor`의 실행 정책에 따라 동일 탭 RESET_PAGE를
최대 한 번 수행할 수 있다. 결정을 영속한 뒤 ACK하고 행동하며,
복구해도 slot 이후 claim을 재사용하지 않는다.

## 5. 성공·안전 기준

- 설정과 다른 매장·날짜·인원·시간 슬롯을 클릭하지 않는다.
- dry-run의 슬롯 click은 0회다.
- 선택 조건이 일치하지 않으면 다른 테이블·메뉴로 대체하지 않는다.
- 추가 상품 수량을 변경하지 않는다.
- 결제금액이 사용자 상한을 넘으면 제출하지 않는다.
- 일반결제, 모호한 CatchPay 상태와 선택 약관을 조작하지 않는다.
- outer/PIN claim 뒤 결과 불명 상태는 재제출하지 않는다.
- URL이나 단일 문구만으로 `COMPLETED`를 만들지 않는다.
- 사용자 중지와 종료 시각 뒤 새 click·submit을 시작하지 않는다.
- raw PIN과 민감한 폼 값은 저장·로그·진단하지 않는다.
- 상태와 실행 근거를 Side Panel과 telemetry에서 확인할 수 있다.

## 6. 비범위와 제한

- 로그인 자동화, CAPTCHA·대기열 우회
- 비공개 Catchtable API 직접 호출
- 일반결제와 실측되지 않은 CatchPay 미등록 화면
- 잘못된 PIN·닫힌 PIN 화면·결과 불명 상태의 자동 재시도
- full reload 뒤 결제·제출 자동 재개
- 유료 scheduled job을 위한 PIN 저장
- 취소 자리 감시와 예약 자동 취소
- 멀티 매장·멀티 탭·대체 인원 선택
