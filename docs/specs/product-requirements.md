# 오픈런 MVP 제품 요구사항

## 1. 제품 정의

사용자가 미리 준비한 Catchtable 예약 모달에서, 예약 오픈 시각에 목표 날짜를 토글해 슬롯을 갱신하고 원하는 시간 슬롯을 빠르게 선택한다. 실측된 선택적 중간 단계를 거쳐 예약 폼에 도착하면 사용자에게 제어권을 넘기는 개인용 Chrome MV3 확장 프로그램이다.

## 2. MVP 범위

- 단일 매장, 단일 탭, 단일 예약 날짜
- 예약 오픈 일시가 정해진 오픈런 모드
- 사용자가 로그인과 예약 모달 열기, 인원 선택을 사전에 완료
- 서버 시계 오프셋 측정
- 기본 T-3초부터 날짜 토글 리페치
- 우선순위와 허용 범위에 따른 슬롯 선택
- dry-run 감지 모드
- 선택적 테이블 타입·메뉴·예약금 0원 결제 방법 진행
- 예약 폼 도착 즉시 사용자 인계
- 사용자 중지와 감시 종료 시각에 따른 확정적 종료

## 3. 사용자 설정

| 필드 | 필수 | 규칙 |
|---|---|---|
| 식당 URL | 예 | `https://app.catchtable.co.kr/ct/shop/<slug>` |
| 예약 오픈 일시 | 예 | 로컬 UI 입력을 epoch ms로 저장 |
| 예약 날짜 | 예 | `YYYY-MM-DD` |
| 예약 인원 | 예 | 1~20, 사용자가 페이지에서 동일 인원을 사전 선택 |
| 희망 시간 시작/종료 | 예 | 분 단위, 경계 포함 |
| 시간 우선순위 | 아니오 | 허용 범위 안의 `HH:MM` 목록, 앞 항목 우선 |
| 후속 선택 자동 진행 | 아니오 | 기본 false; 끄면 슬롯 선택 직후 인계 |
| 테이블 타입 | 아니오 | `아무거나`, `홀`, `바`, `룸`; 기본 `아무거나` |
| 메뉴명 키워드 | 아니오 | 부분 일치, 비우면 첫 가용 메뉴 |
| 감시 종료 시각 | 예 | 기본 `예약 오픈 일시 + 10분` |
| 페이지 준비 확인 | 예 | 로그인·모달·인원 선택을 사용자가 확인 |
| dry-run | 예 | 기본 true, 해제 시에만 슬롯 클릭 가능 |
| 사전 토글 시작 | 아니오 | 기본 3000ms |
| 토글 간격 | 아니오 | 기본 150ms, 최소 100ms |

`희망 시간`과 `예약 오픈 일시`는 서로 다른 개념이며 UI와 데이터 모델에서 분리한다.

## 4. 실행 흐름

1. 설정을 검증하고 새 RunContext를 생성한다.
2. 식당 매장 URL의 서버 시계를 여러 번 측정한다.
3. 현재 탭·모달·목표 날짜·인접 가용 날짜를 검증한다.
4. 서버 기준 `openAtMs - preOpenLeadMs`까지 대기한다.
5. 인접 날짜와 목표 날짜를 토글한다.
6. 표시 중인 가용 슬롯을 읽고 중복 제거한다.
7. 우선순위 목록을 먼저 적용하고, 없으면 허용 범위 내 이른 시각을 선택한다.
8. dry-run이면 클릭하지 않고 `DRY_RUN_COMPLETED`로 종료한다.
9. 실제 실행이면 클릭 직전 조건과 종료 시각을 재검증하고 한 번만 클릭한다.
10. 후속 선택 자동 진행이 꺼져 있으면 슬롯 선택 직후 `HANDED_OFF`로 종료한다.
11. 옵션이 켜져 있고 테이블 타입 화면이 있으면 설정과 일치하는 항목을 선택한다.
12. 메뉴 선택 화면이 있으면 키워드 일치 메뉴 또는 첫 메뉴를 선택한다.
13. 추가 상품 화면이 있으면 상품을 선택하지 않고 활성화된 `다음`으로 진행한다.
14. 예약금 결제 방법 화면에 `예약금 0원 결제`가 있으면 선택하고 진행한다.
15. `/ct/reservation/form` 도착 즉시 `HANDED_OFF`로 전환한다.

## 5. 성공 기준

- 설정과 다른 날짜 또는 시간 슬롯을 클릭하지 않는다.
- dry-run의 click 호출 수는 0이다.
- 특정 테이블 타입이 없거나 메뉴 키워드가 일치하지 않으면 다른 항목으로 대체하지 않는다.
- 추가 상품 수량 버튼을 클릭하지 않는다.
- 유료 예약금만 가능한 화면에서는 자동 진행하지 않는다.
- 예약 폼의 약관과 최종 `예약하기` 클릭은 0이다.
- 종료 시각 도달 후 날짜 토글과 슬롯 클릭은 0이다.
- 서버 시계 동기화가 실패해도 경고와 함께 명시된 로컬 시계 fallback을 사용한다.
- 상태와 이벤트를 Side Panel에서 확인할 수 있다.
- 브라우저 API 없는 핵심 로직은 단위 테스트할 수 있다.

## 6. 비범위

- 로그인 자동화, CAPTCHA 처리 또는 우회
- 비공개 Catchtable API 직접 호출
- 유료 예약금 선택, 방문 목적, 약관, 결제, 최종 예약 확정 자동화
- 취소 자리 스나이핑
- 멀티 매장, 멀티 탭, 인원 유연 매칭
- 예약 완료 판정과 예약번호 수집

## 7. 2단계 확장점

취소 자리 스나이핑은 같은 설정·Clock·SiteAdapter·상태 이벤트를 재사용하되 30초 이상의 감시 간격을 강제한다. 오픈런 MVP 완료 전에는 구현하지 않는다.
