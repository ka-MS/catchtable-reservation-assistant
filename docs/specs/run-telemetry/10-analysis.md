# 실행 텔레메트리 분석

## 현재 문제

- `runEvents`는 `chrome.storage.local`에 남지만 새 실행 시작 시 전체 삭제돼 최신 실행 한 건만 볼 수 있다.
- 이벤트마다 배열 전체를 읽고 다시 쓰므로 고빈도 날짜 토글을 기록하기 어렵다.
- 날짜 토글 반복, 슬롯 0건, 탐색 횟수와 중간 실패가 기록되지 않는다.
- Background의 검증·탭 이동·Content Script 주입 실패는 상세 이벤트 없이 `activeRun=FAILED`만 남을 수 있다.
- 오류 stack, 단계별 소요 시간, 설정 snapshot과 실행 결과의 연결이 없다.
- Side Panel은 저장 배열 전체를 다시 읽고 최근 50개 DOM을 다시 만든다.

## 설계 근거

- 기록 경로는 동기·비차단이어야 하며 저장·표시를 직접 수행하지 않는다.
- MV3 Service Worker 전역 메모리는 영속 원본으로 사용하지 않는다.
- `chrome.storage.local`은 설정과 현재 상태에 사용하고, 누적 상세 이벤트는 IndexedDB에 저장한다.
- 반복 토글은 클릭별 문자열 로그가 아니라 사이클 단위 구조화 이벤트로 기록한다.
- 전체 HTML, URL query, 입력값, 결제정보는 저장하지 않는다.

## 성공 기준

1. 최근 실행 20건과 실행별 상세 이벤트를 브라우저 재시작 뒤에도 조회할 수 있다.
2. 날짜 토글 매 사이클의 계획·실제 클릭·선택 확인·슬롯 탐색 결과가 남는다.
3. Content 기록 경로는 큐 push 외 비동기 작업을 하지 않는다.
4. 배치는 250ms 또는 20건에 전송하고 Background는 수신 즉시 한 IDB transaction으로 저장한다.
5. `(runId, seq)`로 재전송을 중복 없이 처리하고 ACK 전 배치를 보존한다.
6. 성공·실패·중지·시간초과·인계 시 강제 flush한다.
7. Side Panel은 최근 100개 행만 증분 표시하고 과거 실행을 선택해 조회한다.
8. 파일·HTTP·OTLP 출력은 Repository와 분리된 인터페이스로 확장 가능하다.
