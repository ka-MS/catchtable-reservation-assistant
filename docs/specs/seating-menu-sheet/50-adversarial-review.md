# RT-07 복합 좌석·메뉴 단계 적대적 리뷰

## 발견과 수정

초기 finder는 presentation 안에 checkbox, 필수 메뉴 문구, `확인`만 있으면 결합 단계로 판정했다. 이 조건은 일반 필수 메뉴 바텀시트도 오탐할 수 있다.

다음 조건을 추가했다.

- 각 checkbox가 단일 선택 control을 가진 카드 heading에 연결돼야 함
- 하나 이상의 카드 heading에 `홀`, `테이블`, `바`, `카운터`, `룸` 중 하나가 있어야 함
- 좌석 문구가 없는 일반 필수 메뉴 presentation fixture는 `waiting`이어야 함

수정 후 전체 245 테스트와 dist·독립성 게이트가 통과했다.

## 안전성 확인

- 진행 버튼은 `확인`만 허용한다.
- 선택 control과 진행 버튼은 클릭 시점에 다시 조회한다.
- inspection kind와 fingerprint가 바뀌면 클릭하지 않고 재검사한다.
- 설정과 일치하는 좌석·메뉴 카드가 없으면 blocked 처리한다.
- 예약 폼 이후 약관·결제·최종 예약은 기존 인계 경계를 유지한다.

## 잔여 위험

- `홀 -> 테이블`, `바 -> 카운터` 대응은 야키토리묵 실측에 근거하지만 사이트 용어가 바뀌면 인계될 수 있다.
- 동일 카드에 복수 checkbox가 생기거나 heading 구조가 바뀌면 finder는 안전하게 미지원 처리한다.
- 전체 자동 live E2E는 기존 달력 준비 판정 문제 때문에 RT-07 단계까지 도달하지 못했다. 이 문제를 RT-07 범위에서 우회하거나 함께 수정하지 않았다.
