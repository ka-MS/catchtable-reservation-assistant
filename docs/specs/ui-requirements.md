# Side Panel UI 요구사항

## 1. 목적

Side Panel은 오픈런 설정, 실행/중지, 상태와 이벤트 확인만 담당한다. DOM 자동화 로직을 포함하지 않는다.

## 2. 필드

화면 순서는 사용자의 실행 준비 순서를 따른다.

1. 식당 예약 URL
2. 예약 오픈 일시
3. 예약 날짜와 인원
4. 희망 시간 시작과 종료
5. 시간 우선순위 목록
6. 후속 선택 자동 진행: 기본 꺼짐
7. 테이블 타입: 아무거나, 홀, 바, 룸
8. 메뉴명 키워드: 비우면 첫 메뉴
9. 감시 종료 시각
10. 페이지 준비 완료 확인
11. dry-run
12. 고급 설정: 사전 토글 시작값, 토글 간격, 시계 측정 횟수

## 3. 시간 동작

- 예약 오픈 일시를 변경하면 감시 종료 시각을 `+10분`으로 계산한다.
- 사용자가 감시 종료 시각을 직접 수정한 뒤에는 오픈 일시 변경으로 덮어쓰지 않는다.
- 저장 값은 epoch ms이며 `datetime-local`은 UI 경계에서만 변환한다.
- 감시 종료가 오픈 시각보다 빠르면 시작 버튼을 비활성화하고 오류를 표시한다.
- 현재 시각이 감시 종료를 지났으면 시작할 수 없다.

## 4. 우선순위 입력

- `HH:MM` 값을 추가·삭제·위아래 이동할 수 있어야 한다.
- 중복 시간을 저장하지 않는다.
- 허용 범위 밖의 우선순위는 입력 오류로 처리한다.
- 우선순위가 비어 있으면 허용 범위 내 이른 슬롯을 선택한다.

## 5. 실행 안전성

- dry-run 기본값은 켜짐이다.
- dry-run을 끄면 슬롯과 실측된 중간 단계를 진행한 뒤 예약 폼에서 사용자에게 넘긴다.
- 후속 선택 자동 진행이 꺼져 있으면 테이블 타입과 메뉴 설정을 비활성화하고 슬롯 클릭 직후 인계한다.
- 페이지 준비 확인이 없으면 시작할 수 없다.
- 실행 중 설정 필드는 잠그고 중지 버튼만 활성화한다.

## 6. 상태 표시

- 현재 상태의 한국어 라벨
- 서버 시계 오프셋과 측정 품질
- 예약 오픈까지 남은 시간 또는 경과 시간
- 마지막 동작과 선택 후보
- 최근 이벤트 최대 50개
- 종료 결과: dry-run 완료, 사용자 인계, 사용자 중지, 시간 초과, 실패

## 7. 접근성과 레이아웃

- 모든 input은 연결된 label을 가진다.
- 오류는 필드 근처와 상단 상태 영역에 텍스트로 표시한다.
- 키보드만으로 설정과 실행이 가능해야 한다.
- 고급 설정은 기본 접힘 상태로 두어 핵심 필드가 먼저 보이게 한다.
