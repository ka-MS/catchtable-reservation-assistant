# Side Panel UI 요구사항

## 1. 목적

Side Panel은 오픈런 설정, 실행/중지, 상태와 이벤트 확인만 담당한다. DOM 자동화 로직을 포함하지 않는다.

## 2. 필드

화면 순서는 사용자의 실행 준비 순서를 따른다.

1. 식당 예약 URL
2. 예약 오픈 일시
3. 예약 날짜와 인원
4. 예약 페이지 준비: 자동 준비 또는 현재 준비된 모달 사용
5. 희망 시간 시작과 종료
6. 시간 우선순위 목록
7. 후속 선택 자동 진행: 기본 꺼짐
8. 테이블 타입: 아무거나, 홀, 바, 룸
9. 메뉴명 키워드: 비우면 첫 메뉴
10. 감시 종료 시각
11. dry-run
12. 고급 설정: 사전 토글 시작값, 토글 간격, 시계 측정 횟수

## 3. 시간 동작

- 예약 오픈 일시를 변경하면 감시 종료 시각을 `+10분`으로 계산한다.
- 사용자가 감시 종료 시각을 직접 수정한 뒤에는 오픈 일시 변경으로 덮어쓰지 않는다.
- 저장 값은 epoch ms이며 `datetime-local`은 UI 경계에서만 변환한다.
- 감시 종료가 오픈 시각보다 빠르면 시작 버튼을 비활성화하고 오류를 표시한다.
- 현재 시각이 감시 종료를 지났으면 시작할 수 없다.

## 4. 우선순위 입력

- `HH:MM` 값을 추가·삭제·위아래 이동할 수 있어야 한다.
- 중복 시간을 저장하지 않는다.
- 허용 범위 밖의 우선순위는 입력 오류로 처리한다.
- 우선순위가 비어 있으면 허용 범위 내 이른 슬롯을 선택한다.

## 5. 실행 안전성

- dry-run은 사용자가 명시적으로 켜는 안전 점검 모드다.
- dry-run을 끄면 슬롯과 실측된 중간 단계를 진행한 뒤 예약 폼에서 사용자에게 넘긴다.
- 후속 선택 자동 진행이 꺼져 있으면 테이블 타입과 메뉴 설정을 비활성화하고 슬롯 클릭 직후 인계한다.
- 자동 준비는 목표 식당으로 이동하고, 현재 페이지 사용은 활성 탭의 매장 일치를 요구한다.
- 실행 중 설정 필드는 잠그고 중지 버튼만 활성화한다.

## 6. 상태 표시

- 현재 상태의 한국어 라벨
- 서버 시계 오프셋과 측정 품질
- 헤더 아래 고정 배너에 오픈 카운트다운을 `오픈까지 H:MM:SS`(24시간 이상은 `N일` 접두)로 표시
- 카운트다운은 최신 시계 보정 오프셋이 있으면 서버 시계 기준, 없으면 로컬 시계 기준임을 함께 표시
- 카운트다운 배너는 헤더 내부에 포함해 헤더와 함께 고정하고, 모드·강조 전환 시 크기를 바꾸지 않는다 (1분 미만은 색상만 강조)
- 오픈 후 실행 중이면 현재 단계 배지, 미실행이면 `오픈 경과 +H:MM:SS` 표시
- 오픈 일시를 변경하면 감시 종료 시각을 항상 오픈+10분으로 재설정한다. 같은 패널 세션에서 감시 종료를 직접 수정한 뒤에는 덮어쓰지 않는다
- 이벤트 발생 시각을 `HH:mm:ss.SSS` 형식으로 표시
- 시간 슬롯 클릭 성공 이벤트에 서버 보정 시각과 예약 오픈 대비 `+Nms` 또는 `-Nms` 표시
- 예약 폼 도착 인계 이벤트에도 같은 형식의 서버 시각과 오픈 대비 지연 표시
- 예약 오픈까지 남은 시간 또는 경과 시간
- 마지막 동작과 선택 후보
- 최근 이벤트 최대 50개
- 종료 결과: dry-run 완료, 사용자 인계, 사용자 중지, 시간 초과, 실패

## 7. 접근성과 레이아웃

- 모든 input은 연결된 label을 가진다.
- 오류는 필드 근처와 상단 상태 영역에 텍스트로 표시한다.
- 키보드만으로 설정과 실행이 가능해야 한다.
- 고급 설정은 기본 접힘 상태로 두어 핵심 필드가 먼저 보이게 한다.

## 8. 최근 설정과 즐겨찾기

- 실행 검증을 통과한 설정은 히스토리에 자동 저장한다.
- 사용자는 현재 폼을 즐겨찾기에 명시적으로 저장할 수 있다.
- 히스토리와 즐겨찾기는 탭으로 분리하며 각각 최대 20건을 최신순으로 표시한다.
- 저장 행을 선택하면 모든 설정을 폼에 복원한다. 지난 예약 오픈 일시도 임의 변경하지 않는다.
- 단건 삭제와 탭 전체 삭제를 제공하며 전체 삭제에만 확인을 요구한다.
- 저장 목록이 길어져도 Side Panel 전체 길이를 과도하게 늘리지 않도록 목록 내부를 스크롤한다.
