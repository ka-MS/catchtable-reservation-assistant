# Side Panel UI 요구사항

## 1. 책임

Side Panel은 예약 작업 설정, 실행·중지, 저장 설정과 실행 이력 표시를
담당한다. Catchtable DOM 판정과 자동화 로직은 포함하지 않는다.

주요 화면은 예약 작업 목록, 예약 설정과 실행 로그로 나눈다.

## 2. 예약 설정

화면 순서는 사용자의 준비 흐름을 따른다.

1. 식당 URL, 예약 오픈·감시 종료 시각, 예약 날짜·인원
2. 점심·저녁·전체 프리셋, 희망 시간 범위와 우선순위
3. 후속 선택, 결제 방식 정책, 테이블·메뉴 조건
4. 예약 완주, 결제금액 상한, 필수 입력 기본 답변, 일회성 PIN
5. dry-run, 예약 페이지 준비 모드와 고급 타이밍 설정

`현재 탭에서 가져오기`는 활성 Catchtable 탭의 식당 URL과 확인 가능한
날짜·인원만 폼에 반영한다. `식당으로 이동하기`는 항상
`entryMode=auto`, `dryRun=true`인 임시 준비 실행을 사용해 슬롯과
결제를 클릭하지 않는다.

## 3. 기본값과 종속 필드

- 신규 폼의 인원은 2명, 희망 시간은 18:00~20:00이다.
- 후속 선택과 결제 방식 자동 진행은 켜져 있다.
- 결제 방식 정책은 현재 사이트 선택을 허용하는 `selected_allowed`다.
- 예약 완주는 기본적으로 꺼져 있다.
- 최대 결제금액은 0원, 필수 입력 기본 답변은 빈 문자열이다.
- XHR 응답 모드는 신규 폼에서 `empty_exit`이다.
- 저장값에 XHR 모드가 없으면 `off`, legacy true는 `observe`로
  복원한다.

후속 선택이 꺼지면 결제 방식·테이블·메뉴 필드를 비활성화한다.
예약 완주가 꺼지면 결제 상한·필수 입력 답변·PIN을 비활성화한다.

## 4. 시간과 우선순위

- 오픈 일시를 변경하면 종료 시각을 `+10분`으로 다시 계산한다.
- 저장·비교는 epoch ms, `datetime-local` 변환은 UI 경계에서 한다.
- 종료 시각이 오픈보다 빠르거나 이미 지났으면 시작·저장을 거부한다.
- 우선순위는 허용 범위의 중복 없는 `HH:MM` 목록이며 순서를 바꿀 수
  있다.
- 우선순위가 비어 있으면 허용 범위의 이른 슬롯을 선택한다.

## 5. 예약 완주와 secret

- 예약 완주는 사용자가 체크박스로 명시적으로 켠다.
- 결제금액 상한은 0~500,000원 정수다.
- 필수 입력 기본 답변은 비어 있는 필수 텍스트 입력에만 적용한다.
- CatchPay PIN input은 `type=password`, `autocomplete=off`, 최대
  4자리다.
- PIN은 실행 시작 payload를 만든 직후 UI에서 비운다.
- PIN은 draft, 히스토리, 즐겨찾기, 예약 작업과 실행 로그에
  복원하거나 표시하지 않는다.

## 6. 실행 안전성

- dry-run은 슬롯을 감지하지만 클릭하지 않는다.
- actual 실행은 설정에 따라 슬롯 이후 화면과 예약 폼을 처리한다.
- 완주가 꺼지거나 안전 검증이 실패하면 `HANDED_OFF`를 표시한다.
- 실행 중에는 설정과 저장 action을 비활성화하고 중지만 허용한다.
- 초기화는 실행 중 비활성화하며 폼 기본값과 실행 기록을 초기화한다.
- 저장 작업 실행에는 PIN을 저장하지 않는다.

## 7. 상태와 실행 이력

- 현재 상태와 한국어 설명
- 서버 시계 오프셋·품질과 오픈 카운트다운
- 오픈 뒤 실행 단계 또는 경과 시간
- 밀리초 단위 이벤트 시각과 오픈 대비 signed ms
- 슬롯 감지·클릭, 준비 복구, 완주 phase와 terminal 결과
- 최근 실행 20건과 선택 실행의 최근 상세 이벤트 100개
- 전체 실행 CSV와 실패 진단 ZIP

종료 결과에는 `DRY_RUN_COMPLETED`, `HANDED_OFF`, `COMPLETED`,
`STOPPED`, `TIMED_OUT`, `FAILED`를 구분한다.

전체 HTML, URL query, PIN, 입력값과 결제 카드 식별정보는 표시하거나
저장하지 않는다.

## 8. 저장 설정과 예약 작업

- 실행 검증을 통과한 설정은 히스토리에 저장한다.
- 즐겨찾기와 히스토리는 각각 최대 20건을 최신순으로 유지한다.
- 저장 설정은 지난 오픈 일시를 임의 수정하지 않고 폼에 복원한다.
- 예약 작업은 예정·실행 중·완료 상태와 마지막 결과를 표시한다.
- 작업 편집은 draft를 보존하고 저장 완료 뒤 목록으로 돌아간다.
- 완료된 작업은 접힌 목록에서 확인·삭제할 수 있다.

## 9. 접근성

- 모든 input은 연결된 label을 가진다.
- 오류는 필드 근처와 상단 alert에 텍스트로 표시한다.
- 키보드만으로 설정·실행·중지가 가능해야 한다.
- rerender 뒤에도 focus와 disabled 상태가 사용자의 실행 상태와
  일치해야 한다.

## 10. 사용자 온보딩

- 현재 온보딩 버전을 보지 않은 사용자에게만 `예약 작업` 화면에서
  선택형 가이드 시작 카드를 표시한다.
- 가이드는 실제 예약 설정 화면의 영역을 순서대로 강조하며 폼 값,
  draft, PIN, 예약 작업과 실행 상태를 변경하지 않는다.
- `안전 점검`은 일반 실행 권장이 아니라 테스트 작동 시 슬롯 감지만
  확인하는 기능으로 설명한다.
- 가이드가 활성화된 동안 실제 화면은 `inert`와 차단 레이어로 잠그고,
  강조된 대상도 pointer나 키보드로 조작할 수 없게 한다.
- 투어 컨트롤만 조작할 수 있어야 하며 종료 시 실제 화면의 잠금 상태를
  완전히 복구한다.
- 투어 중 사용자 스크롤을 잠그되 단계 전환에 필요한 프로그램
  스크롤은 유지한다.
- 하단 실행바를 설명하는 단계에서도 실행바는 차단 레이어 아래에 두고
  잘린 강조선을 표시하지 않는다.
- 마지막 `완료`를 누르면 잠금을 해제하고 Side Panel을 맨 위로
  이동한다.
- 건너뛰기, 종료와 완료는 현재 온보딩 버전을 local storage에 기록한다.
- 헤더의 `사용법` 버튼으로 저장 여부와 무관하게 다시 시작할 수 있다.
- 이전·다음·종료와 `Escape`를 지원하고 단계가 바뀔 때 설명 제목으로
  focus를 이동한다.
