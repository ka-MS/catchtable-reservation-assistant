# Side Panel 온보딩 투어 설계

**ID:** SP-024  
**기준일:** 2026-08-05  
**상태:** 완료

## 목표

처음 사용하는 사람이 Side Panel의 실제 예약 설정 화면 위에서 각 입력
영역의 의미와 실행 방법을 순서대로 이해하게 한다. 투어는 설명 계층이며
폼 값, 예약 작업과 실행 상태를 변경하지 않는다.

## 진입과 재진입

- 처음 Side Panel을 열면 `예약 작업` 화면에 가이드 제안 카드를
  표시한다.
- 사용자가 `가이드 시작`을 선택해야만 투어를 시작한다. 자동으로 화면을
  가리거나 진행을 강제하지 않는다.
- `건너뛰기`, 중간 `종료`와 최종 `완료`는 현재 투어 버전을
  `chrome.storage.local.onboardingVersion`에 기록해 제안 카드를 다시
  띄우지 않는다.
- 헤더의 `사용법` 버튼으로 언제든 같은 투어를 다시 시작할 수 있다.
- 재시작도 현재 폼 값을 초기화하거나 저장하지 않는다.

초기 투어 버전은 `1`이다. 단계나 의미가 크게 바뀔 때만 이 값을 올려
기존 사용자에게 새 가이드를 다시 제안한다.

## 표시 방식

Side Panel의 좁은 폭에서 말풍선이 입력란을 가리지 않도록 아래 구조를
사용한다.

1. 대상 영역을 `scrollIntoView`로 화면 안에 배치한다.
2. 대상에 강조 테두리를 표시한다.
3. 설명 카드를 화면 아래에 고정하고 `이전`, `다음`, `종료`를 제공한다.
4. 하단 실행 버튼을 설명할 때만 설명 카드를 위쪽에 배치한다.

설명 카드는 현재 단계와 전체 단계 수를 표시한다. `Escape`는 종료와
같이 동작하며, 단계 제목에 focus를 옮겨 키보드와 스크린리더 사용자가
변경을 인지할 수 있게 한다.

## 단계와 문구

| 단계 | 대상 | 핵심 설명 |
|---|---|---|
| 1 | 새 예약 작업 제목 | 현재 입력값을 바꾸지 않고 예약 설정 화면을 순서대로 살펴본다. |
| 2 | 언제 예약할까요? | 현재 탭에서 식당 URL을 가져오고 오픈 일시, 감시 종료, 방문 날짜와 인원을 입력한다. |
| 3 | 어떤 자리를 찾을까요? | 허용 시간 범위와 시간 우선순위를 구분한다. 우선순위가 없으면 범위 안의 이른 슬롯을 사용한다. |
| 4 | 어떻게 진행할까요? | 후속 선택을 켜면 테이블·메뉴 등 실측된 단계를 진행하지만 예약 완주가 꺼져 있으면 예약 폼에서 인계한다. |
| 5 | 예약을 완주할까요? | 명시적으로 켠 경우에만 약관·CatchPay·최종 예약을 진행한다. 금액 상한과 일회성 PIN의 의미를 경고한다. |
| 6 | 실행 모드 | `안전 점검`은 실제 사용자 기본 모드가 아니라 테스트 작동 시 슬롯 감지만 확인하는 기능이다. 실제 예약에서는 끈 상태를 사용한다. |
| 7 | 예약 저장·지금 시작 | 저장은 오픈 시각 자동 실행, 지금 시작은 즉시 실행이다. 저장 작업은 PIN을 보관하지 않는다. |
| 8 | 사용법 버튼 | 실행 결과는 `실행 로그`에서 확인하고, 헤더의 `사용법`으로 투어를 다시 볼 수 있다. |

## 안전 경계

- 투어는 checkbox, select, input과 draft를 변경하지 않는다.
- 투어 시작·이동·종료는 `PANEL_START`, `SCHEDULE_JOB` 또는 다른
  background command를 전송하지 않는다.
- PIN을 읽거나 복사하거나 저장하지 않는다.
- 실행 중에도 읽기 전용 설명은 볼 수 있지만 실행 제어 상태는 바꾸지
  않는다.

## 구현 경계

- 단계 상태와 DOM 강조는 `sidepanel/onboarding-tour.ts`가 소유한다.
- Side Panel `index.ts`는 화면 전환과 onboarding version 읽기·쓰기만
  연결한다.
- 외부 투어 라이브러리는 추가하지 않는다. 현재 8단계에 필요한 최소
  DOM 제어만 구현한다.
- Catchtable DOM, background와 content 실행 로직은 변경하지 않는다.

## 검증

1. 첫 사용자에게만 제안 카드가 표시되고 시작 전에는 화면을 가리지
   않는다.
2. 시작 시 폼 화면으로 이동하지만 기존 입력값은 유지된다.
3. 이전·다음 이동마다 대상 강조, 제목, 본문과 단계 수가 일치한다.
4. 마지막 완료, 건너뛰기, 중간 종료와 `Escape`가 버전 `1`을 저장한다.
5. `사용법`으로 저장 여부와 무관하게 다시 시작할 수 있다.
6. 투어 전체에서 실행·저장 command와 PIN 접근이 없다.
7. `npm run check`와 `git diff --check`가 통과한다.
8. 실제 Side Panel에서 좁은 폭, 스크롤, 하단 액션바 단계와 키보드
   focus를 확인한다.
