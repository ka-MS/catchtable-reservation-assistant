# 사이드패널 UX 개선 설계

**기준일:** 2026-07-12
**선행:** `docs/specs/scheduler/20-design.md` (3화면 구조 구현 완료, 실사용 피드백 반영)
**참고:** 사용자 제공 목업(`catchtable_ui_improvement_mockup.html`)

## 문제 진단 (실사용 피드백)

1. **하단 액션바가 콘텐츠를 가린다.** `.action-bar`가 `position: fixed` + 1열 grid라 폼 화면에서 목록으로/예약 저장/지금 시작 3개 버튼이 세로로 쌓여 약 160px를 차지하는데, 본문 하단 여백은 104px 고정이라 '최근 설정' 영역을 덮는다.
2. **버튼이 조잡하다.** 홈의 전폭 "새 예약 작업" 버튼과 세로로 쌓인 하단 버튼들이 화면을 압도한다.
3. **완료 작업이 계속 쌓여 보인다.** 종료 이력을 최근 20개까지 보관하므로 홈 목록이 완료 카드로 밀려난다.
4. **폼 화면에서 실행 로그가 안 보인다.** 저장·시작 직후 상태를 확인하려면 화면을 옮겨야 한다.
5. **화면 전환이 발견하기 어렵다.** "목록으로"가 하단 버튼 하나뿐이라 현재 위치와 이동 가능한 화면이 드러나지 않는다.

## 목업 평가

| 목업 요소 | 판단 | 근거 |
|---|---|---|
| 상단 세그먼티드 내비(작업/예약 설정/실행 로그) | **채택** | 화면 위치·전환을 상시 노출. 하단 "목록으로" 버튼 제거 가능 |
| "+ 새 예약"을 타이틀 행의 컴팩트 버튼으로 | **채택** | 전폭 버튼 제거, 피드백 #2 해소 |
| 액션바 2버튼 1열 grid, 폼 화면에서만 표시 | **채택** | 피드백 #1·#3 해소. 높이가 고정 여백 안에 들어옴 |
| 완료 작업 접기("완료된 작업 N개 보기 ▾") | **채택** | 홈은 활성(예정·실행 중) 작업만 기본 노출 |
| 폼 하단 미니 로그(최근 기록 + 전체 보기) | **채택** | 피드백 #5. 기존 이벤트 데이터의 읽기 전용 재사용 |
| 실행 중지 버튼을 실행 화면 본문으로 이동 | **채택** | 액션바를 폼 전용으로 단순화 |
| 필터 칩(예정/실행 중/완료 카운트) | **비채택** | 접기 토글과 역할이 겹침. 작업 수가 적어(한도 10) 과함 |
| 실행 모드 select(단계별 실행 범위) | **비채택** | 기능 수술. 기존 dry-run·후속 선택 옵션과 중복 |
| 파이프라인 progress dots | **보류(후속)** | 상태 전이 이벤트 매핑이 필요한 신규 기능. 이번 범위는 시각 개선만 |
| 카드 ⋯ 더보기 메뉴 | **비채택** | 메뉴 컴포넌트 신규 도입 대비 이득 없음. 컴팩트 텍스트 버튼 유지 |
| 다크 로그 패널, 로고 등 장식 | **비채택** | 기존 스타일 체계 유지. 외과적 변경 원칙 |

## 화면 구조

헤더에 세그먼티드 내비를 추가하고 세 화면을 전환한다. 기존 `PanelView` 상태와 `setView`를 그대로 쓰되 내비가 유일한 전환 수단이 된다.

```
┌ 헤더 (sticky) ─────────────────────┐
│ 타이틀 · 상태 배지                  │
│ 카운트다운 배너 (기존 로직 유지)     │
│ [ 작업 ] [ 예약 설정 ] [ 실행 로그 ] │  ← 세그먼티드 내비, active 표시
└───────────────────────────────────┘
```

### 작업(홈)

- 타이틀 행: "예약 작업" + 우측 컴팩트 `+ 새 예약` 버튼(전폭 버튼 제거).
- 활성 작업(예정·실행 중)만 기본 목록으로 렌더한다. 정렬은 기존 openAt 오름차순.
- 그 아래 `완료된 작업 N개 보기 ▾` 텍스트 토글. 접힘이 기본값이고, 펼치면 finished·missed 작업을 updatedAt 내림차순으로 보여준다. N은 finished+missed 개수.
- 카드 구성·버튼(편집/삭제/로그 보기)은 기존 유지.

### 예약 설정(폼)

- 기존 카드 구성 유지. 편집 진입 시 타이틀을 "작업 편집"으로 바꾼다.
- '최근 설정' details 아래에 **미니 로그** 카드를 추가한다: 최신 이벤트 3건(시각 + 메시지)과 "전체 보기" 링크(실행 로그 화면으로 전환). 실행 이력이 없으면 "아직 실행 기록이 없습니다." 한 줄.
- 액션바(fixed)는 이 화면에서만 표시하고 `예약 저장 | 지금 시작` 2버튼을 한 줄(grid 2열)로 배치한다. 오류 문구는 버튼 위 한 줄 유지.

### 실행 로그

- 기존 실행 기록 패널 유지. 패널 헤더 우측에 `실행 중지` 버튼을 이동한다(비실행 시 비활성).
- 액션바는 표시하지 않는다.

## 레이아웃 규칙

- `.action-bar`: `grid-template-columns: 1fr 1fr`, 폼 화면 외에는 `hidden`. 본문 하단 여백은 폼 화면에서만 액션바 높이(약 84px)를 확보하고 다른 화면은 일반 여백으로 되돌린다(`body[data-view]` 또는 view 클래스로 제어).
- 세그먼티드 내비: 목업의 pill 스타일(연회색 트랙 + 흰색 active)을 기존 색 체계(hex)로 옮긴다.
- 자동 전환 규칙 유지: 실행 시작 순간 실행 로그 화면으로 1회 전환. 내비로 언제든 다른 화면 이동 가능.

## 동작 변경 없음 (명시)

- 저장/시작/중지/편집/삭제의 메시지 계약과 background 로직은 그대로다. 이 설계는 사이드패널 표현 계층만 바꾼다.
- 카운트다운 소스 규칙(홈=다음 예정 작업, 폼=폼 입력값, 실행=활성 실행)은 유지한다.

## 테스트 전략

- 뷰 모델 순수 함수로 분리해 검증: 활성/완료 분리와 토글 라벨(`jobListModel(jobs)` — `{ active, done, doneLabel }`), 미니 로그 슬라이스(`miniLogModel(events)` — 최신 3건과 빈 상태 문구).
- 화면 전환·액션바 표시는 기존 관례대로 수동 검증 항목으로 남긴다.

## 수동 검증 항목

1. 폼 화면에서 '최근 설정'을 펼쳐도 액션바에 가리지 않는다.
2. 세 화면 전환이 내비로 동작하고 active 표시가 정확하다.
3. 홈에서 완료 작업이 기본 접힘이고 토글로 펼쳐진다.
4. 폼 미니 로그에 최근 실행 기록이 보이고 "전체 보기"가 실행 화면으로 이동한다.
5. 실행 중지 버튼이 실행 화면 본문에서 동작한다.
