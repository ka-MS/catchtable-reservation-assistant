# 예약 폼 변형 복원력과 실패 근거 관측

**상태:** 진행
**착수일:** 2026-08-06
**부모 패키지:** [CatchPay 예약 완주](../00-index.md) (SP-022)
**구현 승인:** 2026-08-06 사용자 명시 승인 (범위 1~5 그대로 진행)

## 목표

`run-45c3327b`가 예약 폼에서 `intent_mismatch`로 인계된 원인을 제거하고,
같은 종류의 실패가 다시 나면 **진단 번들만으로 원인이 특정되도록** 실패
근거를 남긴다.

## 배경

스시 호시카이 2026-09-08 오후 6:30 실행이 폼 도착 직후 baseline 검사에서
인계됐다. 인계 사유에는 `intent_mismatch` 코드만 있었고 어떤 비교가
깨졌는지가 없어, 원인 특정에 실사이트 재판독이 필요했다.
재판독 결과는 [site-behavior §12.21](../../../analysis/site-behavior.md)에
기록했다.

## 범위

| # | 항목 | 결정 |
|---|---|---|
| 1 | 폼 intent 검증의 시각 비교 | 제거 |
| 2 | 방문예정 목록 확인의 시각 비교 | 제거 |
| 3 | 최종 버튼 판정 | `자동결제로 예약하기` 단일 상수 → `예약하기` suffix, "정확히 1개" 유지 |
| 4 | 실패 근거 관측 | 어댑터 → coordinator → terminal 이벤트 → 진단 스냅샷 |
| 5 | 회귀 고정 | 24시간제 시각·`예약하기` CTA 표본 fixture |
| 6 | 완료 문구 판정 | `자동결제로 예약을 완료했습니다` 정확일치 → `예약을 완료했습니다` suffix |

6은 착수 시 범위 밖이었다. 1~5 수정 뒤 사용자 E2E에서 실제 예약이
생성됐는데도 완료 문구 불일치로 `COMPLETED`에 도달하지 못했고,
그 자리에서 성공 화면을 실측([§12.22](../../../analysis/site-behavior.md))해
근거가 생겨 범위에 넣었다.

## 범위 밖

- 결제 수단 선택·전환 action. 기존대로 하지 않는다.
- 표기 없는 필수 textarea의 자동 입력. `[필수]` 표기가 판정 근거이며
  표기 없는 입력은 대상이 아니다.
