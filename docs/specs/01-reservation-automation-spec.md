# Catchtable Reserve Assistant Specification

## 1. 목적

캐치테이블에서 사용자가 이미 로그인한 Chrome 탭을 감시하다가, 사용자가 지정한 예약 조건과 일치하는 예약 가능 상태가 나타나면 즉시 다음 예약 단계를 클릭하는 개인용 Chrome 확장 프로그램을 만든다.

이 프로그램의 역할은 예약 페이지에서 이미 표시된 상태 변화를 빠르게 감지하고 정상 UI 흐름을 진행하는 것이다. 서버의 접속 대기열, 좌석 배정 순서, 결제 승인 결과를 우회하거나 보장하지 않는다.

## 2. 제품 원칙

- Chrome 확장 프로그램(Manifest V3)으로 제공한다.
- React, UI 프레임워크, 외부 런타임 라이브러리를 사용하지 않는다.
- TypeScript와 순수 HTML/CSS/JavaScript만 사용한다.
- 자동화 엔진은 캐치테이블 페이지 안의 Content Script에서 실행한다.
- UI는 확장 프로그램 Side Panel에서 제공한다.
- 사용자의 실제 로그인 세션과 페이지의 정상 버튼 클릭만 사용한다.
- 설정과 결과 이력은 `chrome.storage`에만 저장한다. 비밀번호, 쿠키, 결제정보는 읽거나 저장하지 않는다.

## 3. 사용자 흐름

1. 사용자는 Chrome에서 캐치테이블에 직접 로그인하고 목표 식당의 예약 페이지를 연다.
2. Side Panel에서 감시 조건을 입력한다.
3. 사용자가 `감시 시작`을 누르면 Content Script가 현재 탭의 예약 UI를 관찰한다.
4. 날짜, 인원, 시간 조건에 맞는 예약 버튼이 보이면 즉시 클릭한다.
5. 다음 화면이 기대한 상태로 전환됐는지 검증한다.
6. 예약 진행이 막히거나 자리가 사라지면 재시도 상태로 전환한다.
7. 예약금 안내의 비최종 `확인`은 결제 정보 화면으로 진행한다. 최종 약관 동의, 결제·예약 확정 또는 CAPTCHA가 필요한 단계에서는 자동화를 멈추고 사용자에게 넘긴다.

## 4. 기능 범위

### 4.1 예약 조건

필수 입력:

- 식당 예약 페이지 URL
- 인원
- 예약 날짜
- 희망 시작 시간과 종료 시간

선택 입력:

- 특정 시간 우선순위 목록
- 재시도 종료 시각
- 성공 후 알림 여부

조건은 감시를 시작하기 전에 검증한다. 현재 열린 탭의 URL이 설정한 식당 URL과 맞지 않으면 감시를 시작하지 않는다.

### 4.2 감시와 즉시 동작

- Content Script는 `document_start`에 주입한다.
- 예약 UI의 변경은 `MutationObserver`로 감지한다.
- 조건이 일치하면 인위적인 `setTimeout` 지연 없이 정상 DOM 클릭을 한 번 수행한다.
- 한 번의 상태 변화에 대해 같은 예약 버튼을 중복 클릭하지 않는다.
- 탭을 새로 열거나 URL을 이동하는 경우에도 현재 감시 상태를 복구한다.

### 4.3 지속 재시도

"무한 리트라이"는 사용자가 중지하거나 종료 시각에 도달할 때까지 지속하는 재시도를 뜻한다. 빠른 연속 클릭이나 무제한 새로고침 루프를 뜻하지 않는다.

- 예약 가능 UI가 새로 렌더링되면 즉시 다시 평가한다.
- 클릭 후 자리가 사라졌거나 일시적 화면 오류가 나면 다음 유효 상태 변화에서 다시 시도한다.
- 네트워크 오류처럼 화면 상태 변화가 없는 경우에만 제한적인 재확인 타이머를 사용한다.
- 서버 대기열, 로그인 만료, CAPTCHA, 수수료/결제 확인, 접근 제한 응답을 감지하면 재시도를 일시 정지하고 이유를 표시한다.
- 사용자는 언제든지 Side Panel에서 재시도를 중지하거나 다시 시작할 수 있다.

### 4.4 상태 표시

Side Panel은 다음 정보를 항상 보여준다.

- 현재 상태
- 감시 중인 탭과 식당 페이지
- 입력된 예약 조건
- 마지막 감지 시각
- 마지막 동작과 결과
- 재시도 횟수
- 중지 또는 일시 정지된 이유

성공, 중지, 오류, 사용자 확인 필요 상태에서는 브라우저 알림을 보낼 수 있다.

## 5. 자동화 상태 전이

```text
IDLE
  -> ARMED        조건 검증 완료
  -> STOPPED      사용자 중지

ARMED
  -> WATCHING     대상 예약 UI 확인
  -> PAUSED_AUTH  로그인 필요

WATCHING
  -> CANDIDATE    일치하는 예약 가능 상태 감지
  -> RETRYING     일시적 오류 또는 예약 불가 결과
  -> EXPIRED      종료 시각 도달

CANDIDATE
  -> ACTING       버튼 클릭 시작

ACTING
  -> VERIFYING    다음 화면 전환 대기

VERIFYING
  -> SUCCESS      예약 진행 성공 화면 확인
  -> RETRYING     자리 소진 또는 진행 실패 확인
  -> CONFIRMING_DEPOSIT  예약금 안내 확인 필요
  -> PAUSED_USER  최종 약관, 결제, CAPTCHA 등 사용자 확인 필요

CONFIRMING_DEPOSIT
  -> VERIFYING    예약금 안내의 비최종 확인 클릭
  -> PAUSED_USER  안내 화면을 인식하지 못함

RETRYING
  -> WATCHING     다음 유효 상태 변화 또는 재확인
  -> EXPIRED      종료 시각 도달
  -> STOPPED      사용자 중지
```

## 6. 성능 기준

확장 프로그램은 페이지 상태가 이미 브라우저에 반영된 뒤의 반응 시간을 최소화한다. 캐치테이블 서버의 대기열과 예약 배정 지연은 이 기준에서 제외한다.

- 외부 라이브러리와 원격 코드를 포함하지 않는다.
- Content Script는 `document_start`에서 준비된다.
- DOM 변경을 감지한 뒤 조건 일치 여부를 동기적으로 판단한다.
- 조건 일치가 확인된 뒤 다음 클릭 호출까지의 로컬 목표는 p95 50ms 이하로 둔다.
- 실행 중 설정을 메모리에 유지하고, `chrome.storage` 쓰기는 설정 변경과 결과 기록 시점으로 제한한다.
- 예약용 탭을 하나 유지하여 탐색과 재로딩 비용을 줄인다.

## 7. 기술 설계

### 7.1 구성 요소

| 구성 요소 | 책임 |
| --- | --- |
| Side Panel | 조건 입력, 시작/중지, 상태와 이력 표시 |
| Content Script | 예약 DOM 관찰, 조건 판정, 클릭, 화면 전환 검증 |
| Service Worker | 탭 연결, 메시지 중계, 저장소, 브라우저 알림 |
| `chrome.storage` | 사용자 조건, 마지막 상태, 결과 이력 |

Content Script는 속도가 필요한 판정과 클릭을 담당한다. Manifest V3 Service Worker는 상시 실행을 보장하지 않으므로 지속 감시 루프의 실행 주체로 사용하지 않는다.

### 7.2 메시지

- Side Panel -> Service Worker: 설정 저장, 감시 시작, 감시 중지
- Service Worker -> Content Script: 현재 조건 전달, 시작/중지 명령
- Content Script -> Service Worker: 상태 변경, 동작 결과, 사용자 개입 요청
- Service Worker -> Side Panel: 최신 상태 전달

메시지는 작은 구조화 객체만 사용하며, 클릭 시점에는 메시지 왕복을 기다리지 않는다.

### 7.3 페이지 어댑터

캐치테이블의 실제 DOM 구조를 관찰한 뒤 다음 항목을 페이지 어댑터로 구현한다.

- 날짜 선택 상태 읽기 및 변경
- 인원 선택 상태 읽기 및 변경
- 시간 슬롯 목록 읽기
- 예약 가능 슬롯 판별
- 슬롯 클릭
- 로딩, 대기열, 로그인, CAPTCHA, 정책/결제, 성공, 실패 화면 판별

선택자는 실제 캡처한 페이지 구조를 기준으로 최소한으로 작성한다. 추측으로 범용 선택자 엔진을 만들지 않는다.

## 8. 비범위

- 계정 생성, 로그인 자동 입력, 쿠키 또는 비밀번호 저장
- CAPTCHA 우회
- 대기열 우회 또는 서버 API 비공개 호출
- 결제 또는 취소 수수료 동의의 자동 확정
- 다수 계정, 다수 탭, 다수 식당을 통한 예약 경쟁 자동화
- 예약권 재판매 또는 타인 계정 대행
- 서버, 모바일 앱, React 기반 웹 애플리케이션

## 9. 오류 처리 원칙

- 로그인 필요: `PAUSED_AUTH`로 전환하고 사용자 로그인 후 재개한다.
- CAPTCHA 또는 추가 인증: `PAUSED_USER`로 전환하고 자동 동작을 중지한다.
- 예약금 안내: 제목과 단일 `확인` 버튼을 검증한 뒤 결제 정보 화면까지 진행한다.
- 최종 약관 또는 결제·예약 확정: `PAUSED_USER`로 전환한다.
- 조건에 맞는 자리가 없음: `WATCHING`을 유지한다.
- 클릭 후 예약 불가: `RETRYING`으로 전환하고 중복 클릭 없이 다시 감시한다.
- 페이지 구조를 인식하지 못함: `PAUSED_USER`로 전환하고 진단 정보를 표시한다.

## 10. 검증 기준

1. 확장 프로그램을 Chrome 개발자 모드에서 로드할 수 있다.
2. Side Panel에서 조건을 저장하고 동일한 값이 다시 표시된다.
3. 대상 탭에서 감시 시작과 중지가 동작한다.
4. 모의 예약 페이지에서 조건과 일치하는 슬롯이 DOM에 추가되면 한 번만 클릭된다.
5. 클릭 뒤 성공, 실패, 사용자 확인 필요 상태를 각각 올바르게 전환한다.
6. 실패 상태에서 중복 클릭 없이 재시도 상태를 유지한다.
7. 로그인, CAPTCHA, 결제 확인 화면에서는 자동 클릭하지 않는다.
8. 조건 일치 DOM 변경부터 클릭 호출까지의 시간을 기록해 p95 50ms 목표를 검증한다.

## 11. 구현 전 확인 필요 사항

- 실제 캐치테이블 예약 페이지의 URL 형식과 예약 플로우
- 날짜, 인원, 시간 슬롯의 실제 DOM 구조
- 예약 가능/불가, 대기열, 로그인, CAPTCHA, 예약금, 결제, 성공 화면의 식별 방법
- 최종 사용자 확인이 필요한 정확한 단계

이 확인을 마친 뒤 Content Script의 페이지 어댑터를 구현한다.
